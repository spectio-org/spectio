## For the Progress page

The Task 9 section of [P3-M2](../../progress/W5/P3-M2.md) is not written yet. It should carry:

- **Assumption (CR-P3T09-04 (r4)).** Snakemake 9 needs `--cores` (local) or `--jobs` (SLURM). When the launch has no workflow profile and `engines.extra_args.snakemake` holds none of `--cores`, `--jobs`, `-c`, `-j`, the head passes `--cores all` on the local executor and `--jobs 100` on SLURM. 100 is Spectio's own cap (`SLURM_JOBS` in `headscript.py`), twice the `jobs: 50` of `tests/pipelines/synthetic/snakemake/profiles/slurm/config.yaml`; whether sites' per-user limits (`MaxSubmitJobs`) want less is **[to be validated]**. With a profile, the profile sets them.
- **Limit (CR-P3T09-06 (r4)).** With a workflow profile, `[slurm] partition` and `account` from `spectio.toml` are not passed to Snakemake: `--default-resources` on the command line would replace the profile's whole `default-resources`. The profile must name them. Merging the two (reading the profile's YAML) was left out: profiles come as `config.yaml` or versioned files, in list or mapping form.
- **Native ID (SEC-P3T09-04 (r4)).** The local launcher's native ID is `<pid>.<start time in clock ticks>`, not a bare PID. Task 10 (tmux) chooses its own.
- **Interface.** `RunnerLoop` takes `settings` and `end_grace_s`, which the plan's signature does not have; `Launcher` gains `forget(ids)`.
- **Dependency on Task 7.** `--logger spectio` is rendered as the plan says; the tests use stub engines.
- **Hand-off to Task 30 (CR-P3T09-11 (r4), CR-P3T09-06 (r2), SEC-P3T09-05 (r2)).** `head.pid`, `head.exit`, `cancel` and `launch-failed.json` are per run, not per launch: scope them by launch, or clear them when a new launch starts.
- **Hand-off to Task 17 (CR-P3T09-04 (r3)).** A run cancelled before its head starts ends `cancelled` only if the cancel endpoint moves it to `cancelling` before it enqueues the command; carry an end-to-end case into Task 17's tests.
- **Known limit (CR-P3T09-R5-04).** A `--profile` in `engines.extra_args.snakemake` is not taken as setting `--cores` or `--jobs`; give the profile through the launch's profiles.
