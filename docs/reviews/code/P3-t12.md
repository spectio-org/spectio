## Findings

| Id | Severity | Finding | Status |

| CR-P3T12-01 (r1), SEC-P3T12-01 (r1) | minor | The req. 9 listener check accepted the first listener on the port at any local address, but the CLI dials 127.0.0.1. The user's own socket on 127.0.0.2:P, listed first in `/proc/net/tcp`, could hide another uid's listener on 127.0.0.1:P, and the server key would go to that uid. | fixed in `439c2b7`: `port_owners(port)` lists every listening uid, and login sends the key only if the set is exactly the caller's uid |
| CR-P3T12-02 (r1) | minor | `test_login_print_link` calls `monkeypatch.undo()` partway through. That reverts every patch of the shared fixture (the settings fixture's `HOME` and `SPECTIO_*`, the `lone_host` patch) while the server runs. `_exchange_live` then uses urllib's default opener, which honours a developer's `http_proxy`: with `http_proxy` set and no `no_proxy`, the live exchange goes to the proxy and the test fails. | **open**, follow-up FU-P3-39 |
| CR-P3T12-03 (r1) | minor | The plan (M3 intro) says Task 12's conftest provides `client` with no session. As built, `client` is still the shared-host client with the API unmounted; the signed-out client is the module-local `anon` fixture. `api/conftest.py` dropped its `TODO(P1 Task 16): a client with no session cookie` without doing it. | recorded: [inbox #105](../inbox.md#105-assumed-the-token-link-as-built-p3-task-12) rule 7, written with this record |
| CR-P3T12-04 (r1) | simplify | The file names `server.key` and `server.json` are defined twice: `KEY_FILE` and `STATE` in `login.py`, `secrets.KEY_FILE` and `serve.STATE` in the server. A rename on one side silently breaks `spectio login`. | **open**, follow-up FU-P3-39 (the CLI package cannot import the server; the constants belong in `spectio`) |
| SEC-P3T12-02 (r1) | minor | The CLI trusts the listener's answer more than it needs to. (a) It prints the URL as returned and checks only the fragment, so the scheme, host and path can point anywhere. (b) `DIRECT` keeps urllib's default `HTTPRedirectHandler`: on a 301, 302 or 303, CPython turns the POST into a GET and copies every header but `Content-Length` and `Content-Type`, so `Authorization: Bearer <key>` follows the redirect to any host. | **open**, follow-up FU-P3-39, before the 0.0.1 release. The listener is the caller's own uid (req. 9), so the exposure needs a process of the user's own |
| SEC-P3T12-03 (r1) | minor | `Started` is a plain `@dataclass`, so its `repr` includes `link`, a first token link with a live ticket. A `repr` in a log, a traceback with locals or a pytest failure message shows a ticket that works for up to 15 minutes. `ServerKey` already uses `repr=False`. | **open**, follow-up FU-P3-39 |
| CR-P3T12-02 (r2) | minor | In the mixed case (the user's own listener plus another uid's on one port) the refusal reads "no server of yours on port P (it is held by uid X)". One of the listeners is the user's. Refusing is still right. | **open**, follow-up FU-P3-39 |
| CR-P3T12-03 (r2) | simplify | `others = sorted(owners - {os.getuid()})` is built only to read `others[0]`. | **fixed** by the batch `code-simplifier` in `7d6c80f` ([P3-B01](P3-B01.md#simplification)): the list is gone, the message uses `min(owners - {uid})`. CR-P3T12-02 (r2) stays **open**, follow-up FU-P3-39 |
| SEC-P3T12-01 (r2) | minor | Check-then-dial race: the owner check reads `/proc/net/tcp`, then the key is read and a new connection is dialled. If the user's server exits in that gap and another uid binds 127.0.0.1:P, the key goes to that uid. The window is small, the key is stale once the server stops, and the code was like this before the fix. | **open**, accepted for 0.0.1 **[to be validated]**; FU-P3-39 looks for a way to narrow it |
| SEC-P3T12-02 (r2) | minor | `port_owners` counts listeners at every local address, including ones a dial to 127.0.0.1 can never reach (127.0.0.2, the node's own address). A co-tenant on a shared login node can bind `<node-ip>:P` or `127.0.0.2:P` next to the user's server, and `login --print-link` then refuses for good and blames that uid. It fails closed, so nothing leaks. The first-entry code could be blocked the same way. | **open**, follow-up FU-P3-39: count only 127.0.0.1, 0.0.0.0, `::` and `::ffff:127.0.0.1` |
| SEC-P3T12-03 (r2) | minor | `serve.py` still uses the first-entry `port_owner` for its "port taken (uid N)" message. The user's own socket on 127.0.0.2:P listed before another uid's on 127.0.0.1:P makes `serve` name the user's own uid. Information only: no key is sent. | **open**, follow-up FU-P3-39 |
| DOC-P3T12-01 | minor | **Found by `doc-writer`, not by a reviewer:** `test_req2_ticket_stored_hashed` flips the last character of a session secret to `"A"` and expects `valid()` to be false. A 32-byte `token_urlsafe` has 43 characters, the last one carries 4 bits, and `A` is one of 16 possible values, so the test fails about 1 run in 16 (6.4 % in 100 000 draws; it failed once in the first 2 runs here, then passed 6 of 6). The code is right; the test is not. | **fixed** before the PR: the test flips to `"B" if secret[-1] == "A" else "A"`; 8 runs of the test passed |
