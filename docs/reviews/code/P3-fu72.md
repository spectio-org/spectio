## What the step does

- **Transport.** On a SLURM environment, and in local mode on a host that `shared_host()` calls shared, `spectio serve` listens on `spectio.sock` in its database directory and serves the API and the screens there. It binds no TCP port. Local mode on a machine only the user uses keeps `127.0.0.1:<port>`. On TCP, `create_app` still leaves the API unmounted on a shared host.
- **Refusals, exit 2:** a database directory that is not a real `0700` directory of the user; a socket path over 107 bytes; a file at the path that is not a socket; a socket a server answers on. A stale socket is removed and bound again. The socket is `0600` and removed at a clean stop.
- **`server.json`** gets `socket` beside `port`. `spectio login --print-link`, `serve --detach` and `spectio open` use it. The start text gives `ssh -N -L 127.0.0.1:<port>:<socket> <user>@<node>`.
- **Files:** `serve.py`, `app.py` and `store/db.py` in `spectio-server`; `cli/login.py`, `cli/open.py`, `cli/serve.py`, `open_remote.py` and `ports.py` in `spectio`; the tests below; the guides, the spec and the log.
- **Tests:** `tests/security/test_unix_socket.py` (17 cases, a real uvicorn on a socket), `test_open.py` (the tunnel to a socket, and 7 bad sockets), `test_detach.py` (the tunnel text, a restart after a dead server).
