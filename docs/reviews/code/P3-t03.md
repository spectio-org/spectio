## Findings

The finding texts are summarised from the fix commits' messages and the round summaries. A pair such as CR-P3T3-01 / SEC-P3T3-03 is one problem found by both reviewers.

| Id | Severity | Finding | Status |
|---|---|---|---|
| SEC-P3T3-01 | major | Memory and time of one read were unbounded: only lines were capped, not the bytes of a read or the size of an event's `data`; on the round-1 head, 500 lines took 788 MiB. | fixed in `35fb19e`: a read takes at most `max_bytes` (`MAX_READ_BYTES`, 2 MiB) from the files, skipped bytes included; `data` may hold at most `MAX_EVENT_NODES` (4096) values and `MAX_EVENT_DEPTH` (32) levels (`test_req6_read_stops_at_max_bytes`, `test_req6_memory_bounded_on_nested_lines`, `test_req6_event_node_cap`, `test_req6_event_depth_cap`) |
| SEC-P3T3-02 | major | No owner or mode check: `.spectio`, `events` or a spool file of another user, or one writable by others, was read. | fixed in `35fb19e`: `.spectio` and `events` must be private directories of the user (`fstat` after the `O_NOFOLLOW` open), else `PermissionError`; a file of another owner, or writable by group or others, is refused (`foreign_owner`, `writable_by_others`; the `test_req12_*` tests) |
| CR-P3T3-01 / SEC-P3T3-03 | major / minor | An `OSError` on one file stopped the whole read. | fixed in `35fb19e`: `ELOOP`, `EACCES` and `ENXIO` refuse the file (`symlink`, `unreadable`); any other error is counted `read_error` and the file is retried (`test_unreadable_file_refused_and_the_next_one_read`, `test_read_error_retried_next_read`) |
| CR-P3T3-02 / SEC-P3T3-04 | minor | The directory listing was unbounded. | fixed in `35fb19e`: at most `MAX_DIR_ENTRIES` (16 384) entries per read (`test_directory_listing_cap`) |
| CR-P3T3-03 / SEC-P3T3-05 | minor | Junk names could take the cursor's file slots and grow the cursor. | fixed in `35fb19e`: slots go to this launch's spool files only; a name outside the grammar is kept as a short hash, `MAX_BAD_NAMES` (64) at most; the rest is counted through a high-water mark, `#excess` (`test_junk_names_leave_the_slots_to_spool_files`, `test_spool_file_cap`) |
| CR-P3T3-04 / SEC-P3T3-06 | minor | The fresh-environment import check resolved its dependencies anew, unlocked. | fixed in `cd78f18`: each environment installs `uv export --frozen --no-dev --no-emit-workspace --package <pkg>` with `--require-hashes`, then the workspace packages with `--no-deps` |
| CR-P3T3-05 / SEC-P3T3-07 | minor | api §14.1 did not state the reader's rules: the caps, the grammar, the drop reasons, the cursor. | fixed by the docs of this step: [api §14.1](../../specs/api-and-data-model.md#141-driven-runs-001), "Dropped and counted, never executed", and its bounds table |
| CR-P3T3-06 | minor | A file of exactly `MAX_FILE_BYTES` that grew was never counted `file_too_large`. | fixed in `35fb19e` (`test_req6_file_of_exactly_max_bytes_counted_when_it_grows`) |
| CR-P3T3-07 | minor | The files read came from the listing, so a listing cut at `MAX_DIR_ENTRIES` could skip a file admitted earlier. | fixed in `8058fb0`: the files read come from the cursor, in name order (`test_admitted_files_read_past_the_listing_cap`) |
| CR-P3T3-08 | minor | Unended lines in earlier files can use up the byte budget of a read and starve later files. It needs a buggy or hostile writer. | **open**, follow-up (Progress page) |
| CR-P3T3-09 / SEC-P3T3-10 | minor | An event over the node or depth cap was counted `invalid`, and was fully parsed before the check. | fixed in `8058fb0`: it is counted `too_complex`; a line with more than 2 × (4096 + 16) of `[`, `{` and `,` is dropped before it is parsed (`test_too_complex_line_not_parsed`) |
| CR-P3T3-10 | minor | A file gone between the listing and the open was counted `read_error`. | fixed in `8058fb0`: it is skipped (`test_file_gone_between_listing_and_open`) |

| SEC-P3T3-08 | minor | Cursor values were not checked on entry. | fixed in `8058fb0`: every value is checked on entry (an `int`, not a `bool`; `REFUSED` or 0 to `MAX_FILE_BYTES` for a file; `REFUSED` for a name hash; a count for `#excess`); anything else is reset and counted `bad_cursor`; too small `max_lines` or `max_bytes` raise `ValueError` (`test_bad_cursor_values_refused`, `test_budgets_too_small_refused`) |
