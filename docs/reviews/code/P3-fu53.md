### The design (Step B), condensed

- **Before.** `parse_sacct(text, wanted: set[str])` (`runner/sacct.py:173-231` at `18383abd`): a second job line for one ID poisons the row (`:200-202`). The WorkDir check came later, in `failure._answers` (`:443-447`), from `Accounting.step` (`:403-410`). So a RESIZING record plus the final one gave no row and, after `MAX_TRIES`, `not_found` (SEC-P3T34-06); and a forged line with any WorkDir removed the real row (SEC-P3T34-04).
- **API.** `parse_sacct(text, wanted)` returns `{job: {normpath(WorkDir): SacctRow}}`; `sacct_jobs(wanted, timeout_s, *, sacct)`; `check_ids` on the keys; `SacctLimiter` still queues IDs.
- **Rules.** (1) A job line is a candidate only if its normalised WorkDir is in the expected set; other lines are dropped, not poisoning. (2) A step line attaches to the job line just before it for that ID, and counts only if that line is a candidate. (3) Of several candidates for (ID, directory), RESIZING ones are dropped; exactly one left is kept; two or more give no row; only RESIZING gives no row (not terminal, `failure.py:63-66`). A state rule, not "the last line", since the order between instances is not verified. (4) No candidate: no entry, asked again up to `MAX_TRIES`, then None.
- **Callers.** `Accounting._call` builds `{job: {where of each run asking}}`; `Accounting.step` reads `found[job][normpath(where)]`; `_answers` stays as a second guard; the `sacct.json` format is unchanged.
- **Open questions put to the reviewers.** B1: sum the steps of a matching RESIZING instance? B2: stop queueing jobs whose `where` is None? B3: add a resize case to the `slurm-mini` check?

### Not taken from the design

- The expected directories carry each run's launch time (`{job: {dir: launch}}`), which the design's `Mapping[str, Collection[str]]` did not; two runs that expect one job in one directory share the earlier launch. That case needs two runs with the same work or launch directory, which `run_paths` does not make.
- `TZ=UTC` is added to the call's environment so `Submit` is read in one zone whatever the server's or the node's. Whether `sacct` honours `TZ` is **[to be validated]** on `slurm-mini`.
