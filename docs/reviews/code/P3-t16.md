It adds:

- `packages/spectio-server/src/spectio_server/auth/writes.py` (new): the write checks of req. 7, moved out of `api/browser.py`. A method other than `GET` and `HEAD` gets `403` (`/problems/cross-site`) for a missing `Origin` or one other than `http://<Host>`, port included; `411` when `Transfer-Encoding` is sent; `415` when a non-empty body is not `application/json`; `413` when `Content-Length` is not digits or is over `MAX_BODY` (1 MiB). A request with no body, such as `:cancel`, needs only the `Origin`;
- `app.py`: the install order is now writes, session, browser, host. Starlette runs the last one installed first, so a request goes Host allow-list, cross-site check (`api.browser`), session, write checks. A signed-out write gets `401`. The exchange and `auth/links` skip the session check and still go through the write checks;
- `api/browser.py`: keeps only the cross-site check (`Sec-Fetch-Site`, or a foreign `Origin` or `Referer`, on every method). Its docstring says why it stays: the `SameSite=Strict` cookie does not cover a page on another port of the same loopback host (HTML standard, "same site", **[to be validated]**);
- docstrings of `app.py`, `auth/middleware.py` and `api/relaunch.py` give the new order; the `TODO(P1 Task 16)` of `relaunch.py` is gone;
- tests: `tests/security/test_req7_writes.py` (16 cases from 10 functions: the plan's six, then body size, the check running after the session, the exempt exchange and `auth/links`, and no `Access-Control-*` header on a preflight, a `GET`, a `POST` and `/auth/link`). The three `TODO(P1 Task 16)` markers of inbox #87 became no-session `401` cases: `test_version_behind_session` (`test_read.py`), `test_stream_needs_session` (`test_stream.py`) and `test_req16_relaunch_origin_csrf` (`test_relaunch.py`). They passed at once, since the session middleware has existed since Task 12;
