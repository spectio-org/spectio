### security-reviewer

All security findings are minor, and none changed code in `7c54157`. The first three came in both rounds 1 and 2 (the same text, numbered again as SEC-P3T22-01 to -03 (r2)); round 3 found nothing.

| Id | Where | Finding | Status |

| SEC-P3T22-01 (r1, r2) | `tests/slurm/e2e.sh`, native mode | Root writes into and reads from directories the run's user owns. After the first launch `$DATA/e2e` belongs to `spx`. On the next launch root runs `rm -rf`, `mkdir -p`, `cp` into `$DATA/e2e/` (which writes through a planted symlink) and `printf > "$e/bin/$tool"` there, so `spx` can make root write fixed content at paths it chooses. On a failure, root runs `tail` on `"$e"/runs/*/launch/.spectio/head.out`; `spx`, or a head or task it runs, can make that file a symlink to `/etc/shadow`, and root prints it into the log. In `mini` mode the same `tail` runs as the runner user on the host through the bind mount. | **open**, FU-P3-68: run these steps as the run's user, or refuse symlinks |
| SEC-P3T22-02 (r1, r2) | `e2e.sh`, `e2e_client.py` | The database directory is a fixed path in `/tmp` (`/tmp/spectio-e2e-<engine>-db`). Another local user who creates it first makes the run fail: `rm -rf` as the run's user cannot remove it, and `spectio init`'s owner check refuses it (`cli/init.py:43-48`). In round 1 the report saw a worse case (the client opening a foreign `spectio.db`); round 2 found the product check stops any takeover, leaving a denial of service. | **open**, FU-P3-68: a private directory under `$DATA/e2e/<engine>` |
| SEC-P3T22-03 (r1, r2) | `e2e.sh install`, `cluster.sh up` | `uv tool install` of the wheels resolves the server's dependencies fresh from PyPI and ignores `uv.lock`; `tmux` is whatever the node image's distribution offers. This copies the user install path and `tests/packaging/test_wheel.sh:77`, so it is not new, but the job now runs on every push to `packages/**`. A compromised transitive release could only falsify its result or artifact (`contents: read`, no secrets). | **open**, FU-P3-68, with FU-P3-47's `uv export --frozen` and hashes |
| SEC-P3T22-04 (r1) | `cluster.sh up` | The `tmux` install runs as root in the submitter for every profile: `apt-get update` and an unpinned distro package, a network step in every matrix job. Packages are signed, so the risk is low. | **open**, with CR-P3T22-04 (r1) |

With `E2E_USER=root` the whole run is privileged, which breaks the premise of §4.1 and §15.3 that the run user is unprivileged; a value starting with `-` becomes a `useradd` option. | **open**, FU-P3-68: a name pattern and a refusal of uid 0 |
