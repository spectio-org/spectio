## Findings

### UX-G2-01 · major · The state cards squeezed the Pipeline field to a few pixels at 1024 px

- **Where:** `LiteLaunch.dc.html`, `LiteLaunchSnakemake.dc.html`, the two state cards at the foot of the page.
- **Evidence:** in the first draw, the Pipeline, Revision and Load row was a grid with a fixed Revision column. At 1024 px each card is about 360 px wide. The Pipeline input shrank to about 40 px ("/g/de"), and its help text wrapped one word per line.
- **Fix:** the row is a wrapping flex row: Pipeline `flex: 999 1 280px`, Revision `flex: 1 1 220px` up to 260 px, then Load. In a narrow card, Revision and Load go to a second line.
- **Status:** applied in `9a61c33`. Checked at 1440 and 1024 px.

### UX-G2-02 · minor · The Revision placeholder was clipped at 1440 px

- **Where:** the same row in the Pipeline section of both desktop boards.
- **Evidence:** at a 160 px basis, the placeholder read "tag, branch or comm".
- **Fix:** a 220 px basis. The placeholder now fits.
- **Status:** applied in `9a61c33`.

### UX-G2-03 · minor · The repeated Load and Launch buttons in the state cards did not name their card

- **Where:** the state cards of the three boards.
- **Evidence:** a screen reader's button list read "Load" three times and "Launch" three times, with no way to tell which card each belongs to (CLAUDE.md: per-row labels name the row).
- **Fix:** each card's Load and Launch buttons carry `aria-describedby` with the card's heading ("No guess: both files found", "Refused: a file:// URL"…). Each card's engine group is labelled by "Engine" and the card heading.
- **Status:** applied in `9a61c33`.

### UX-G2-04 · major · `GET /workflows:inspect` cannot feed the guess line or tell "both" from "neither"

- **Where:** [P1](../../plans/P1-walking-skeleton.md) Task 17 (interface of `GET /api/v1/workflows:inspect`), [api §5](../../specs/api-and-data-model.md#5-endpoint-catalogue-api-v1); the boards' "Guessed from main.nf", "both found" and "neither found" texts.
- **Evidence:** inspect returns `engine` (`null` for both and for neither) and `engine_version` for that engine only. It does not return the files it found. The board needs them to say *which* file the guess came from, and to tell the two no-guess cases apart. G5's `guessEngine(files: string[])` has no input either. "Where it runs" also shows an engine version; once the user presses the other engine, that version has no source.
- **Proposal:** inspect also returns `engine_files` (those of `main.nf`, `Snakefile` and `workflow/Snakefile` that exist), and an engine version per engine, or `GET /version` lists both. `guessEngine` takes `engine_files`.
- **Status:** deferred to `/apply-findings` (P1 Task 17 and api §5 are specs; not edited in a board step).

### UX-G2-05 · minor · ui-spec §4.6 does not give the wording and placement drawn here

- **Where:** [ui-spec §4.6](../../specs/ui-spec.md#46-launch-and-relaunch), note 2026-10-29.
- **Evidence:** the note says "two buttons" and "a path on the machine or a Git repository and revision". It says nothing about:
    - the Revision field ("Git only", disabled with its reason for a path);
    - the "Guessed from <file>" line beside the buttons;
    - the no-guess text, and that Launch stays disabled until an engine is chosen;
    - the refusal messages;
    - Launch in the page head, with its reason beside it;
    - Launch appears twice, in the page head and at the end of the aside, with one shared state (UX-G2-09);
    - the short-name grammar: `owner/repo` is read as GitHub, `nf-core/<name>` as `https://github.com/nf-core/<name>` (UX-G2-12);
    - Revision is required for a Git source;
    - on a prefilled launch, the engine line names the source run ("Nextflow, as in rnaseq-2026-10-25") instead of the guess (UX-G2-13).
- **Proposal:** extend the note with these points and link the three boards.
- **Status:** deferred to `/apply-findings`.

### UX-G2-06 · minor · mvp-0.0.1 §2 still describes the old launch form

- **Where:** [mvp-0.0.1 §2](../../specs/mvp-0.0.1.md#2-features-and-where-they-are-specified), the note of 2026-10-29 above the screenshots, and the `lite-launch` alt text.
- **Evidence:** the note says the boards "show the look before depictio's Paper chrome and a detected engine". The alt text names "a pipeline directory and Load, the detected engine". The regenerated screenshot now shows the Pipeline and Revision fields and the two engine buttons, with Nextflow pressed.
- **Proposal:** once G2 and G3a are merged, update the note and the alt text: "a Pipeline field with Revision and Load, the Engine buttons with Nextflow pressed and 'Guessed from main.nf'".
- **Status:** deferred to `/apply-findings`.

### UX-G2-07 · minor · Two toggle buttons stand for a one-of-two choice

- **Where:** the Engine group of the three boards.
- **Evidence:** P2 §10.2 and G5's component test fix the control as two `<button aria-pressed>`. A radio group is the native one-of-two pattern. Toggle buttons are right only if pressing one releases the other, and if none can be pressed while there is no guess.
- **Proposal:** keep the buttons, as planned. Task 19's component test also checks that pressing one releases the other, and that the group keeps its label.
- **Status:** open, for Task 19.

### UX-G2-08 · minor · The disabled Revision field cannot take focus

- **Where:** the Revision field when the Pipeline field holds a path.
- **Evidence:** a disabled input is skipped by Tab, so a keyboard user does not reach its reason ("Read as a directory…"). Sighted users see the reason beside the field.
- **Proposal:** keep it for 0.0.1. Task 19 may instead hide Revision until the Pipeline field reads as a repository.
- **Status:** open, for Task 19.

### UX-G2-09 · major · Launch existed only in the page head

- **Found by:** `ux-reviewer`, round 1.
- **Where:** `LiteLaunch.dc.html`, `LiteLaunchSnakemake.dc.html`, the aside.
- **Evidence:** at 1024 px the aside stacks about 1850 px below the head, so the form ended with no submit button. ui-spec §4.6 puts the launch button in the aside, with its reason.
- **Fix:**
    - Launch stays in the page head, and a second Launch ends the aside, with the same disabled reason (one shared state).
    - The aside is `position: sticky; top: 8px` from 1200 px.
    - `#launch-what` reads "Starts the engine in a new tmux session on login1…", with no "at the top of the page".
    - "Launch appears twice" is added to UX-G2-05's list.
- **Status:** applied in `7114560`.

### UX-G2-10 · major · "Neither file found" asked for a choice that cannot work

- **Found by:** `ux-reviewer`, round 1.
- **Where:** `LiteLaunchSnakemake.dc.html`, the "No guess: neither file found" card.
- **Evidence:** the card said "Choose the engine". But P1 Assumption 2 has Launch check that the chosen engine's file exists, so with neither file every choice fails.
- **Fix:**
    - The card keeps both buttons unpressed. Launch is disabled with "No main.nf or Snakefile in this directory: check the path", whatever is pressed.
    - A new card on `LiteLaunch`, "Guess overruled: Snakemake chosen, no Snakefile here": Snakemake pressed; beside it, "workflow/Snakefile not found: Launch will refuse. Guessed: Nextflow (main.nf)"; Launch disabled with that reason.
    - Both cards depend on UX-G2-04: the server must say which files it found.
- **For `/apply-findings`:** the entry-file list (`main.nf`, `Snakefile`, `workflow/Snakefile`) may miss a lowercase `snakefile` and a Nextflow `manifest.mainScript` other than `main.nf` **[to be validated]**, for the fact-checker.
- **Status:** applied in `7114560`; the entry-file list is deferred with UX-G2-04.

### UX-G2-11 · minor · No fetching or fetch-failure state for a Git source

- **Found by:** `ux-reviewer`, round 1.
- **Where:** `LiteLaunchSnakemake.dc.html`.
- **Fix:**
    - A "Fetching… at v2.1.2" card: Load busy (`aria-busy="true"`), with the status "Cloning https://github.com/… (once per revision)".
    - A "Not fetched: revision not found" card, with the field error on Revision. Its note lists the other failures: repository not found or private, no network from login1, ssh asking for a password or a passphrase.
- **For Task 17:** that the clone runs without prompts (no terminal, so ssh fails instead of asking) is **[to be validated]**.
- **Status:** applied in `7114560`.

    - The short-name grammar is added to UX-G2-05's list.

### UX-G2-13 · minor · A prefilled launch said "Guessed from main.nf"

- **Where:** `LiteLaunch.dc.html`, which is prefilled from rnaseq-2026-10-25.

### UX-G2-14 · minor · G5's tests do not reach `GET /workflows:inspect`

- **Found by:** `ux-reviewer`, round 1.
- **Where:** [P2 §10.6 G5](../../plans/P2-execution.md#106-g5-tests-for-the-engine-buttons-and-the-git-source).
- **Evidence:** the refused-URL and revision tests post to `POST /runs`, with fields `workflow.location` and `workflow.revision`. Load calls `GET /workflows:inspect` first, and that call also fetches from Git.
- **Proposal:** the same tests also hit `GET /workflows:inspect`, with fields `location` and `revision`.
- **Status:** deferred to `/apply-findings`.
