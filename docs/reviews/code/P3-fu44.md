## Pre-review

Condensed from the pre-review note of 2026-11-08 (design, then both reviews). It covered two steps; this branch builds **Step A only**. Step B (sacct, inbox #116 rule 10 (b)) is step P3-fu53 and is not recorded here.

### Design, Step A

1. Settings, tmux on PATH and `spectio_server` importable, else exit 2.
2. A server already runs: `login.new_link` answers, so print the link here, exit 0 (idempotent; a foreground `spectio serve` counts too). server.json on another node: exit 2 without `--force`. No server.json, or a stale one: step 3.
3. The session `spectio-server` exists: wait for its pane, never kill it. Else `new-session -d -P -F … -s spectio-server -c / <argv…>`, where argv is a list: `env NAME=value… python -m spectio serve --pane [--force]`. `-c /` because `-c` is a tmux format (SEC-P3T10-01). A "duplicate session" is a race: list again and wait.
4. Wait, polling, for a server.json of this node whose PID is the pane's, then ask it for a link and print it here. The pane ended: exit 2. Time out: exit 3, the session left.
5. The pane (`--pane`, hidden) prints "New link: spectio login --print-link" instead of the link.

Nothing secret is in argv, the pane or the tmux environment: the port comes from server.json, checked as `spectio login` checks it, and the ticket from `POST /api/v1/auth/links` with the server key, only after the port's listener is the user's uid. Code: `runner/tmux.py` (a module-level `run_tmux`, the pane parser, `SERVER_SESSION`), `cli/serve.py`, `cli/main.py`, `spectio_server/serve.py`, a new `spectio/__main__.py`. Tests named first: 14, plus a real-tmux roundtrip under the `tmux` marker. Open questions: (1) exit 3 is new for `serve`; (2) which `SPECTIO_*` variables reach the pane; (3) the unused first ticket in `--pane`; (4) `--detach` never replaces a stale server.json itself (the child does, under its lock).

### What the build found against the design

- **A word that ends in `;`.** tmux 3.4 splits a command on an argument that ends in `;` (`C=x;` made `/bin/sh` an unknown command), and turns `\;` into `;` (reproduced here). So every argv word that ends in `;` is refused with exit 2, naming the variable (`test_detach_refuses_a_word_tmux_would_split`). `#`, `$`, `~`, `\` elsewhere and quotes arrive literally.
- **`set-option -t =spectio-server`** fails inside the chain on tmux 3.4 ("no such session"); `=spectio-server:` works. With `destroy-unattached on` in `~/.tmux.conf`, the session started without the chained option was gone at once, and with it it stayed (reproduced). The real-tmux test fails when the chain is removed.
- **"No session" messages** of tmux 3.4: `can't find window: spectio-server` (a tmux server, no such session), `no server running on …`, `error connecting to …`; the fake prints `can't find session`.
- **The real test's socket.** The test gives tmux a private `TMUX_TMPDIR`, so a private socket, rather than `-L`: `--detach` has no socket option and reaches tmux the way the launcher does.
