### SEC-1 · major · `wave-approved` accepted any labeller, any base, and manual runs could take any alias

- **Where:** `previews.yml`, job `if`, alias step
- **Evidence:** any same-repo PR with a `W<n>` title could repoint `wave-w<n>`, and `workflow_dispatch` could overwrite `main` or `pr-*`.
- **Problem:** "validated wave" is an integrity claim that the code did not enforce.
- **Proposal:** require the owner as sender and `main` as base; refuse reserved aliases on manual runs; consider an environment with a required reviewer.
- **Found by:** security-reviewer
- **Status:** applied (`311d13e`, tested in `test_alias.py`). The required-reviewer environment is an option for Thomas **[to be validated: plan support]**. The residual risk is SEC-5.

### SEC-2 · minor · PR-head code runs with the Cloudflare token; wrangler's dependencies are not locked

- **Where:** `previews.yml`, the versions and deploy steps
- **Evidence:** a same-repo PR controls the scripts that hold the token.
- **Problem:** a token holder could be modified by a PR.
- **Proposal:** a base checkout for the script, and a lockfile for wrangler.
- **Found by:** security-reviewer
- **Status:** accepted as residual risk. With `pull_request`, the workflow file itself comes from the PR, so a base checkout adds nothing; the fork guard is the boundary. The lockfile is left to Renovate (spec §7.1).
