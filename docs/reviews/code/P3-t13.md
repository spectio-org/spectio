# Code review · P3 Task 13, session cookie per host port

`review-code` on `autopilot/P3-t13`, base `6a0ee0f`, 2026-11-06. The step is [P1 Task 13](../../plans/P1-walking-skeleton.md#task-13-session-cookie-153-req-3), the second sign-in task of milestone M3 ([P2 §3](../../plans/P2-execution.md#3-m3-served-safely)). It adds:

- `packages/spectio-server/src/spectio_server/auth/middleware.py`: `cookie_name(host_header)`, which gives `spectio_session_<port of Host>`, and `spectio_session_80` when `Host` has no port or no ASCII digits after its last colon; the middleware reads only the cookie of this `Host` port;
- `auth/routes.py`: the exchange sets that cookie (`HttpOnly`, `SameSite=Strict`, `Path=/`, no `Domain`);
- tests: `tests/security/test_req3_cookie.py` (14 tests: the three of the plan, 11 cases of `cookie_name`), and the sign-in of `tests/api/conftest.py`, `test_req4_req7_browser.py` and `test_req2_secrets.py` moved to the named cookie;
- `tests/e2e/global-setup.ts`, `global-setup.unit.ts`, `skeleton.spec.ts`: `portOf` takes the scheme's default port (CR-P3T12-05), the goto error is rethrown with the ticket masked (CR-P3T12-03), and the `EventSource` assertion reads the real `Cookie` header of the request for this port's session cookie, instead of a `toBeUndefined` on `headers()`, which never lists cookies. The two P3-t12 IDs come from the review of PR #132, named in `.autopilot/journal.md`; they are not the findings of the same number in [P3-t12.md](P3-t12.md).

| CR-P3T13-01 (r1) | minor | The `EventSource` assertion built the expected cookie name from `portOf(target.url)`, which returns 443 for an https URL with no port. The server's `cookie_name` reads the port in `Host` and falls back to 80, and a browser sends `Host` without a port for such a URL. The smoke would have failed wrongly against that target (`base-url.ts` accepts https). | **fixed** in `985ad08`: `sessionCookie(url)` returns `spectio_session_${new URL(url).port \|\| '80'}`, with a unit test for an explicit port, http with no port, https with no port and https:8443. `portOf` is unchanged for `statePath` and the pointer file |
| CR-P3T13-02 (r1) | minor | The comment in `test_req3_other_port_cookie_ignored`, "a browser sends every port's cookies", states a fact about browsers with no source (CLAUDE.md, External facts). | **open**, follow-up FU-P3-40: cite a source or drop the comment. RFC 6265 §8.5 is the candidate **[to be validated]** |
| SEC-P3T13-01 (r1) | minor | Two `Host` parsers disagree. `api/browser.py::_name` takes the text before the first colon and never checks the port; `cookie_name` takes the text after the last colon. `localhost:1:2`, `localhost:abc`, `[::1]x:5` and `127.0.0.1:099999999` pass the req. 4 allow-list and get the cookie names `_2`, `_80`, `_5` and `_099999999`. A browser never sends such a `Host`, and a DNS-rebinding page cannot make `Host` name a loopback host, so nothing can be exploited. But the allow-list and the cookie name rest on two readings of one header. | **open**, follow-up FU-P3-40, owner [P1 Task 14](../../plans/P1-walking-skeleton.md#task-14-host-allow-list-153-req-4) (`auth/host.py`): one parser for both. The collision belongs to the server (`841db01`, outside the fix range), and req. 3 did not document it. | **recorded**: [dev-env §15.3 req. 3 note 2026-11-06](../../specs/dev-environment-and-testing.md#153-001-on-a-cluster-architecture-and-safety-without-accounts) and [inbox #106](../inbox.md#106-assumed-the-session-cookie-as-built-p3-task-13) rule 2. 0.0.1 serves http on loopback only, so the https case needs a reverse proxy the 0.0.1 server does not have |
