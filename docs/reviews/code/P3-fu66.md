## What the step does

- **`up`** installs the missing Ubuntu 24.04 packages with apt (Slurm 23.11.4, slurmdbd, MariaDB 10.11, munge), writes `slurm.conf` and `slurmdbd.conf` in `/etc/slurm` with a marker line, starts munged, MariaDB, slurmdbd, slurmctld and slurmd, adds the cluster `local`, and waits for the node to be idle.
- **`down`** stops the daemons and MariaDB; packages and configs stay. **`status`** lists them.
- **Guards**, built-ins and `id` only, before any apt call, daemon start or file write: root only; no inherited `SLURM_CONF` that is not its own; a `slurm.conf` or `slurmdbd.conf` without the marker line (or a dangling link in their place) is foreign; `down` needs its own `slurm.conf`; `up` without it is refused while a Slurm daemon runs or a configless cache exists.
- **The database password** is made per install into a root-only file, reaches MariaDB on stdin and `slurmdbd.conf` through `sed`, and is never printed, never in a shell variable and never on a command line. MariaDB is started with `--bind-address=127.0.0.1`.

**A side effect found by the worker.** With `/etc/slurm/slurm.conf` present, the default `uv run pytest -q` had 35 failures (24 in `test_efficiency.py`, 11 in `test_process_status.py`), all "This machine looks shared (`/etc/slurm/slurm.conf` exists)" from `spectio_server/app.py:73` `shared_host()`. Both modules import `client_for` from `tests/api/conftest.py` but sit outside `tests/api/`, so they missed its autouse `lone_host` fixture and relied on a host with no `slurm.conf`. The fix is test-only: each now imports `lone_host` (`# noqa: F401`). Earlier P3 steps passed only because no `slurm.conf` existed.

**What the checks prove and do not prove.**

- The two configless cache paths (`/run/slurm/conf`, `/var/spool/slurmd/conf-cache`) are **[to be validated]** against the Slurm configless documentation, and the guard has no test for them (fixed constants).
