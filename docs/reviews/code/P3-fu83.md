## What the step does

- **Task logs.** `tests/pipelines/synthetic/bin/synth.py` wraps every subcommand in `main()`. It writes deterministic lines, with no time and no host: INFO on stdout (arguments, inputs, progress, outputs, done), one WARN line on stderr, and ERROR lines on stderr when a task fails. The first ERROR line still reads `synthetic failure: …`, which `test_bridge_nextflow.py` looks for. Lines are flushed one by one, so a task killed with SIGKILL (`fail oom`) keeps what it wrote.
- **Verbosity.** The parameter `verbosity` (`quiet`, `normal`, `loud`) is in both schemas (Scenario group) and reaches the task as `SYNTH_VERBOSITY`. `loud` is about 1000 lines and 90 KB per stream, past the 64 KiB tail. An unknown value is refused before any output. The outputs and their checksums do not change; `test_synth.py` pins them at every level.
- **Snakemake rule logs.** Each rule has `log: err=…, out=…` (`<outdir>/logs/<rule>/<job>.err` and `.out`). stdout goes to `.out`; stderr goes to `.err` and is teed to the job's own stream.
- **`fail_demo`.** Nextflow: profile `fail_demo` (`COMPARE`, `treatA`, `exit`). Snakemake: `profiles/fail_demo/config.yaml`. The run ends `failed` with a tool error, after both gates.
- **Collection.** `pyproject.toml` `testpaths` now includes `tests/pipelines/synthetic`, so `uv run pytest` collects `test_synth.py`, `test_snakefile_logs.py` and the existing `test_golden.py`.
