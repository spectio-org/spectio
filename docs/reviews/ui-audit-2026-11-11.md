# UI audit of the built app: design-system consistency (2026-11-11)

An audit of the built Spectio web app after Thomas's request of 2026-11-11: "There is real UI work to redo. Many inconsistencies, bad placements of icons, buttons, etc. For example the notification bar/column is not modern at all. […] I really want everything coherent and consistent." (said in French, translated; [inbox #153](inbox.md#153-assumed-ui-design-system-and-the-notifications-panel-2026-11-11)). The rules that answer it are [ui-spec §12](../specs/ui-spec.md#12-design-system-2026-11-11).

**Method.**

- The app of `origin/autopilot/integration` at `ecd5f25f`, served with `tests/e2e/serve-local.sh --seed-stages`, plus a scratch seeder that added four runs from `tests/fixtures/engine-events` (a failed Nextflow run, a failed Snakemake run, a succeeded run with a long name, a resumed run). No repository file was edited.
- 102 screenshots with Playwright: `d-` desktop at 1440 px, `m-` iPhone 13, `dark-` dark mode, `_d-sheet*` and `_m-sheet*` contact sheets. Nextflow and Snakemake were not installed, so no run started; the app has no admin pages.
- Code read in `web/src` at the same commit for the counts and the file:line references.

**Screenshots.** The PNGs are not committed: they show the state before the rebuild and would churn the media budget ([documentation-system §5](../specs/documentation-system.md#5-media)). They are kept outside the repository with the audit's helper scripts, and the same set is re-taken after the rebuild ([ui-spec §12.15](../specs/ui-spec.md#1215-verification)). Evidence below names a shot by its file name.

**Summary.** 44 findings: 0 blockers, 20 majors, 24 minors. UX-DS-01 to -09 are systematic causes; UX-DS-10 to -42 are seen on one screen; UX-DS-43 and -44 are the notifications panel. Each names its build task of the plan in [inbox #153](inbox.md#153-assumed-ui-design-system-and-the-notifications-panel-2026-11-11).

**Status of all findings:** accepted (assumed — pending Thomas, inbox #153); applied to the spec as ui-spec §12 and the api §5.9 amendment of 2026-11-11; the code follows in the build tasks named on each.

## Systematic causes

### UX-DS-01 · major · The tokens cover colour only

- **Where:** `design/tokens/spectio-tokens.css`, `web/src/shell/theme.ts` (`createTheme` sets no spacing, radius, type scale or `components` defaults); every CSS file under `web/src`
- **Evidence:** 17 font sizes (among them 12.5, 13.5 and 11.5 px), 20 border radii (3 to 24 px and 999), 13 gap values; of 3,704 CSS lines, 21 read a `--mantine-*` variable. Visible in every shot, e.g. `d-home`, `d-runs`, `d-launch-empty`.
- **Problem:** Each screen picks its own numbers, so nothing lines up across screens; this is the root of most findings below.
- **Proposal:** Spacing, radius, type and weight scales as Mantine theme keys, and no raw px outside them ([ui-spec §12.2](../specs/ui-spec.md#122-tokens)).
- **Found by:** UI audit of the built app (Playwright and code reading), 2026-11-11
- **Status:** accepted (assumed, inbox #153); spec applied in ui-spec §12; build tasks 1, 19

### UX-DS-02 · major · Icons in 10 sizes and 5 strokes, six paths outside `icons.tsx`

- **Where:** `Sidebar.tsx:93`, `LaunchPage.tsx:683`, `FoldSection.tsx:87`, `EnvironmentsPage.tsx:31`; paths in `NotificationsBell.tsx:14`, `TopBar.tsx:91`, `Sidebar.tsx:38`, `RunState.tsx:9`
- **Evidence:** sizes 12 to 22 px, strokes 1.6, 1.8, 2, 2.2 and 2.4; BELL, SUN, MOON, FOLD, UNFOLD and SLASH drawn inline. `_d-sheet1`, `_m-sheet1`.
- **Problem:** Icons of one kind look different from screen to screen (Thomas: "bad placements of icons").
- **Proposal:** One size per context, stroke 1.75, every path in `icons.tsx`, a test that rejects inline paths ([ui-spec §12.3](../specs/ui-spec.md#123-icons)).
- **Found by:** UI audit of the built app (Playwright and code reading), 2026-11-11
- **Status:** accepted (assumed, inbox #153); spec applied in ui-spec §12; build task 2

### UX-DS-03 · major · Buttons have no size or placement rule

- **Where:** 110 `<Button>` in `web/src`: 62 with no size, 38 xs, 3 sm, 2 md; `CatalogPage.tsx:33`, `EnvironmentsPage.tsx:61`
- **Evidence:** the page primary is 36 px on Home and Runs, 42 px on Catalog and Environments; dialog footers put Cancel then Delete on the left; Copy appears in three styles. `d-home`, `d-environments`, `d-catalog`, `d-delete-dialog`, `d-profile`.
- **Problem:** The same action has a different weight and place on each screen.
- **Proposal:** One default size, one filled primary at the far right of the page head, overflow in a `…` menu, a dialog footer rule, one Copy pattern ([ui-spec §12.4](../specs/ui-spec.md#124-buttons-and-actions)).
- **Found by:** UI audit of the built app (Playwright and code reading), 2026-11-11
- **Status:** accepted (assumed, inbox #153); spec applied in ui-spec §12; build tasks 3, 9, 18

### UX-DS-04 · major · Danger buttons and field errors use Mantine's default red, below AA

- **Where:** 9 `color="red"` buttons (`DeleteRuns.tsx:117`, `RunHeader.tsx:276`, …); field errors
- **Evidence:** `#FA5252` gives 3.28:1 on white; ui-spec §3.4 asks 4.5:1 for text. `d-launch-errors`, `d-environments-new`.
- **Problem:** Text in failed buttons and errors fails WCAG 2.1 SC 1.4.3.
- **Proposal:** `failed` and `review` Mantine colours from the state tokens (`#B02A2A`, 6.54:1); default `red` never used ([ui-spec §12.4](../specs/ui-spec.md#124-buttons-and-actions)).
- **Found by:** UI audit of the built app (Playwright and code reading), 2026-11-11
- **Status:** accepted (assumed, inbox #153); spec applied in ui-spec §12; build task 1

### UX-DS-05 · major · Seven link classes that conflict

- **Where:** `sp-link`, `sp-text-link`, `sp-link-button`, `sp-run-link`, `sp-env-link`, `sp-quick-link`, `sp-link-end`; `.sp-link-button` in `shell.css:774` (always underlined) and `runs.css:463` (hover only); bare `<a>` in `LaunchPage.tsx:871`

- **Status:** accepted (assumed, inbox #153); spec applied in ui-spec §12; build tasks 1, 3

### UX-DS-06 · major · Four tab or segment patterns, plus native controls

- **Where:** Mantine `Tabs` (run detail), `.sp-segments`, underline file tabs (`runs.css:1299`), sort radios (`ByProcess.tsx:124`); raw `<select>` in `RunDetailPage.tsx:712`, `TaskFiles.tsx:282` and three more; a raw radio in `ProfilePage.tsx:80`

- **Problem:** The same choice is made with four different controls, two of them unstyled.
- **Proposal:** Tabs for views of one object, SegmentedControl for filters, Select for sort and choices, all in accent ([ui-spec §12.9](../specs/ui-spec.md#129-tabs-segments-and-form-controls)).
- **Found by:** UI audit of the built app (Playwright and code reading), 2026-11-11
- **Status:** accepted (assumed, inbox #153); spec applied in ui-spec §12; build tasks 10, 12

### UX-DS-07 · major · The focus ring does not reach Mantine portals

- **Where:** `shell.css:24` scopes the ring to `.sp-shell :focus-visible`
- **Evidence:** menus, modals and drawers show Chromium's default ring (`m-search-open`); route-focus headings with `tabIndex=-1` show a violet box (`d-environments-new`, `d-run-file`).
- **Problem:** Keyboard focus looks different inside every overlay, and a box appears on a heading nobody tabbed to.
- **Proposal:** One global `:focus-visible` rule, none on route-focus targets ([ui-spec §12.11](../specs/ui-spec.md#1211-focus)).
- **Found by:** UI audit of the built app (Playwright and code reading), 2026-11-11
- **Status:** accepted (assumed, inbox #153); spec applied in ui-spec §12; build tasks 1, 6

### UX-DS-08 · major · No shared page-head anatomy

- **Where:** `PageHead` (Home, Runs, Launch, Environments, Catalog, Profile); `RunHeader` (run detail, an engine tile inside a card); Results, file and report pages with a back link and a bare h1; Catalog adds "Back to Launch" above its head
- **Evidence:** `d-run-results`, `d-run-file`, `d-catalog`, `d-run-failed-summary`.
- **Problem:** Titles and actions move from page to page.
- **Proposal:** One `PageHead` on every routed page, no row above it ([ui-spec §12.5](../specs/ui-spec.md#125-page-head)).
- **Found by:** UI audit of the built app (Playwright and code reading), 2026-11-11
- **Status:** accepted (assumed, inbox #153); spec applied in ui-spec §12; build tasks 3, 17

### UX-DS-09 · major · Empty, loading and error states each have their own look
