## What changed

- **`.github/workflows/pipelines-real.yml`** ([spec §11](../../specs/dev-environment-and-testing.md#11-ci-workflows)). Each corpus job now:
    - frees runner disk first, by removing toolchains it never uses and the preloaded Docker images, with plain `rm` and no third-party action. This step runs only on GitHub-hosted runners (`if: runner.environment == 'github-hosted'`);
    - samples free memory and disk every 5 s, and writes the start and minimum values to the job summary and to a `resources.json` artifact;
    - in the nf-core job, prints the last 80 lines of `run.log` when the run fails or is cancelled, and stays green when there is no log;
    - lets a catalog entry name its own `snakefile`.
    - Event values reach the shell through `env:` (`NAME`, `LIMITS`), not through `${{ }}` inside `run:`.
    - The `matrix` job runs the unit tests of `run_corpus.py` first, then builds the matrix with `run_corpus.py --matrix <tier>`, which validates the corpus before printing it.
    - `astral-sh/setup-uv` runs with `enable-cache: false`, so no shared cache is saved from a job that runs third-party code.
    - In the Snakemake job, the workflow's own checkout replaces the workspace. A sparse checkout of `runner_probe.sh` comes first, and the script is copied to `$RUNNER_TEMP`.
- **`tests/pipelines/real/runner_probe.sh`, new:** the free, sample and summary steps, shared by both jobs (`runner_probe.sh free | sample | summary NAME`). `summary` exits cleanly with "no samples" when the job stopped before sampling started.
- **`tests/pipelines/real/run_corpus.py`:**
    - a `clone()` helper also accepts a full commit SHA, for repositories with no release tag. If a clone by SHA fails, it removes the half-made checkout before re-raising;
    - per-entry `env` and `args`;
    - `run.log` is streamed to disk, so a run killed by a full disk or a timeout still leaves its log;
    - `validate()` runs on every invocation. Every ref must be a release tag or a 40-hex commit SHA, never a branch. `repo`, `directory`, `snakefile` and each `args` token must be plain tokens. An error names the entry;
    - `--matrix <tier>` prints the CI matrix lines for `GITHUB_OUTPUT`. The workflow's inline Python is gone.
- **`tests/pipelines/real/test_run_corpus.py`, new:** 5 unit tests: clone cleanup, validation of the current corpus, branch refs and unsafe values rejected, and matrix names.
- **`tests/pipelines/real/corpus.yaml`:**
    - viralrecon 3.0.0 and methylseq 4.2.0 run with `NXF_SYNTAX_PARSER=v1`;
    - ampliseq 3.0.0 gets `--config_profile_contact none --config_profile_url none`;
    - dna-seq-varlociraptor gets its upstream `--configfile`, single-cell-rna-seq its root `Snakefile`;
    - chipseq is pinned to commit `1345df8` of its default branch, `master` (it was `tag: main`, which does not exist);
    - rna-seq-star-deseq2 and rna-seq-kallisto-sleuth get `--retries 2` and `network: [ensembl]`;
    - six catalog entries move to `manual`, each with a `note` that says why;
    - the `runner_limits` comment now gives the measured values; `private` stays 2 CPU / 6 GB / 2 h.
- **`.github/workflows/ci.yml`:** `pipelines-real` is back in `ci-ok`'s `needs` (`ea0f6bf`). D4 had left it out while the corpus was red ([D4](D4.md)).
- **Spec:** [`dev-environment-and-testing.md`](../../specs/dev-environment-and-testing.md):
    - [§10.2](../../specs/dev-environment-and-testing.md#102-real-pipelines-testspipelinesrealcorpusyaml): the tier table with a `manual` column, the new optional keys, corpus validation, the parser and runner constraints, and the re-run rule for entries tagged `network:`;
    - [§11](../../specs/dev-environment-and-testing.md#11-ci-workflows): `ci.yml` and `pipelines-real.yml` as built.

## Why

`pipelines-real.yml` was red: 18 of 23 jobs failed in the nightly run on `main` (run 40463254070), and 5 of 9 in the PR tier on weber8thomas/spectio#16 (run 40535210648). While it was red, it could not gate `ci-ok`.

Prompt: [next-phase.md · T7](../../playbooks/next-phase.md#t7-real-pipeline-corpus-green-in-ci). For each failure, the prompt asks for one of three decisions: a runner limit, an upstream issue, or a corpus bug. No new decision-log entry; the gate design is D4's ([`ci.yml`, inbox #26](../../reviews/inbox.md#26-licences-repository-governance-and-ci-costs)).

**Three causes, none in Spectio's code** (details in the [note, §2](../../research/corpus-ci-2026-10-27.md#2-failure-analysis-and-decisions)):

| Cause | Entries | Decision |
|---|---|---|
| Runner disk: `No space left on device` | 9 failures across 7 nf-core entries (rnaseq and molkart failed in both runs) | runner limit: free disk first, 15 GB → about 46 GB |
| Strict config parser rejects an include missing from the tag | viralrecon 3.0.0, methylseq 4.2.0 | corpus fix: `NXF_SYNTAX_PARSER=v1` (nf-core/viralrecon#606, nf-core/methylseq#607) |
| Upstream breakage in catalog workflows (conda pins, a dead URL, a missing package, Ensembl timeouts) | dna-seq-gatk-variant-calling, chipseq, cyrcular-calling, ONT-AmpSeq, rna-seq-kallisto-sleuth | upstream: moved to `manual`, issue linked where one exists |

Three corpus bugs were also fixed: chipseq's `tag: main`, varlociraptor's missing `--configfile`, and single-cell-rna-seq's `Snakefile` path. ampliseq needed two arguments under Nextflow 26.10's typed params.
