## What changed

- **`dev/versions.env`:** one exact pin per tool, each with its source. Every binary and tarball has a sha256, and every image the doctor runs has a digest. It also holds the on-demand pins (mermaid-cli, mkdocs, mkdocs-material, depictio), which bootstrap never installs. The values are listed in [§1](../../specs/dev-environment-and-testing.md#1-toolchain-pinned-in-devversionsenv) and in the file.
- **Two hash locks:**
    - `dev/snakemake.lock.txt`: Snakemake 9.27.1, the SLURM and Kubernetes executor plugins and their 72 packages, each with `--hash=sha256:`;
    - `dev/npm/package.json` and `package-lock.json`: Playwright 1.63.0 with integrity hashes.
- **`dev/bootstrap.sh [--ci]`:** installs the toolchain in four parallel jobs, each with its own log, and is idempotent. Downloads are checked before they are moved into place. With `--ci` it also starts `dockerd` when nothing else will, and pre-pulls the doctor's images by digest, from `mirror.gcr.io` first.
- **`dev/doctor.sh`:**
    - checks each tool's version against the pin;
    - runs one smoke test per layer: docker, sind, kind, nextflow, snakemake and playwright;
    - exits 1 on the first failure, printing `doctor: FAILED: <tool>`.

    sind and kind are skipped, with the reason, where Docker runs on cgroup v1. `SPECTIO_DOCTOR_STRICT=1` turns a skip into a failure.
- **`dev/lib.sh`:** the paths and the Docker helpers shared by both scripts.
- **`.github/workflows/dev-env.yml`:** bootstrap timed, then the doctor in strict mode on `ubuntu-24.04`; the output goes to the job summary. It runs on pushes that touch `dev/`, weekly, and by hand.
- **Spec** [`dev-environment-and-testing.md`](../../specs/dev-environment-and-testing.md):

    - §4.2: answered;
    - §7.2: a note that `versions.env` now exists;

## Why

The dev spec asked for one bootstrap script that runs in the cloud setup script, in CI and on a laptop, and for a doctor that proves each layer works. [Spike D2](../../research/spike-cloud-env-2026-10-26.md) measured what a cloud session can run. Its findings set the design:

- sind and kind need cgroup v2, so they are proven in CI;
- `dockerd` is not running at session start;
- Docker Hub rate-limits anonymous pulls;
- `releases/latest` URLs are refused.
