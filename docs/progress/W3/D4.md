## What changed

- **`ci.yml`, new:** the one aggregate check that branch protection requires, besides `docs-gate` and `pr-body`, and the place every other check is called from ([`dev-environment-and-testing.md` §11](../../specs/dev-environment-and-testing.md#11-ci-workflows)).
    - A `changes` job reads the PR's merge commit and decides whether the synthetic scenarios or the real-pipeline corpus must run.
    - It calls `security.yml`, `pipelines-synthetic.yml` and `pipelines-real.yml` as reusable workflows.
    - `ci-ok` needs every job, runs with `if: always()`, and fails only when a job ended `failure` or `cancelled`. A skipped pipeline job counts as passing, so no path filter can leave a required check waiting.
- **`security.yml` and `tools/ci/security.sh`, new:** four checks on every PR and push, with no path filter, and weekly on the whole history. The same script runs on a laptop.

    | Check | Tool | Fails on |
    |---|---|---|
    | secret scanning | gitleaks 8.30.1 | any secret in the PR's commits |
    | dependency audit, Python and JavaScript | osv-scanner 2.7.0 | any known vulnerability in a lockfile |
    | SAST, Python and JavaScript | semgrep 1.182.1, `p/python` and `p/javascript` | any finding of severity `ERROR` |
    | workflow linters | actionlint 1.7.12 and zizmor 1.31.1 | any error, and zizmor findings from `low` up |

    Release binaries are checked against their SHA-256 on every run. Exceptions live only in code-owned ignore files; inline `gitleaks:allow` and `nosemgrep` comments do not count.
- **`claude-review.yml`, new:** `spec-reviewer` reviews PRs that touch `docs/**`, `security-reviewer` reviews PRs that change anything else. Findings go to inline comments and one summary comment.
    - It is advisory and never a required check.
    - It is skipped for drafts, fork PRs and bots, and while no Claude secret is set.
    - It checks out the base branch, reads the PR through `git` only, and cannot edit, push, merge or approve.
    - The commands Claude runs get a scrubbed environment and PID isolation, which reduce the risk that a prompt injection posts the Claude credential.
- **`release-please.yml`:** now uses a GitHub App token (`actions/create-github-app-token`), from the `release` environment. While `RELEASE_APP_ID` or `RELEASE_APP_PRIVATE_KEY` is missing, the job warns and skips its steps.
- **`.github/CODEOWNERS`, new:** workflows, `.claude/`, `CLAUDE.md`, `pipeline.yaml`, the autopilot, the scanners and their exception files, the release-please config, and auth and secrets code all need Thomas's review, once branch protection asks for it.
- **Every existing workflow hardened**, so that the linters pass:
    - every action pinned by full commit SHA, with its version in a comment;
    - `persist-credentials: false` on every checkout;
    - no `${{ }}` expansion inside a `run:` script;
    - a `timeout-minutes` on every job, and a `concurrency` group on every top-level workflow.
    - `pipelines-synthetic.yml` and `pipelines-real.yml` became reusable workflows, called by `ci.yml`.
- **A real leak, redacted.** The first gitleaks run found nf-core's Slack webhook URL in six megatest params files (commit `b3c49ea1`). The files are redacted, and `tools/fixtures/megatests.py` now redacts `hook_url` when it curates. The old commit stays in history, listed in `.gitleaksignore`, until a history rewrite (inbox #5).
- **Specs:**
    - [`dev-environment-and-testing.md`](../../specs/dev-environment-and-testing.md): §1 (pins), §8 (Claude review), [§11](../../specs/dev-environment-and-testing.md#11-ci-workflows) (workflows as built, the security checks table, Claude review), [§12](../../specs/dev-environment-and-testing.md#12-versioning-and-releases) (App token wiring and its one-time setup);
    - [`autopilot.md` §8](../../playbooks/autopilot.md#8-pull-requests-and-auto-merge): the protection payload now requires `ci-ok`, `docs-gate`, `pr-body` and code-owner reviews.

## Why

Thomas asked for security checks that are "béton" on every PR, and decided on one aggregate required check, `ci-ok` (inbox #26, R8b DEP-T-001). A path-filtered workflow cannot be required: when a PR skips it, it never reports, and the PR waits for ever. CODEOWNERS covers the paths that steer agents (DEP-T-008). The release-please bot needs an App token, because events created with `GITHUB_TOKEN` start no workflow (inbox #8).

Prompt: [next-phase.md · D4](../../playbooks/next-phase.md#d4-ci-and-claude-in-github). Decisions: inbox #8 and #26, answered 2026-10-27.

## Evidence

All commands ran on 2026-10-27 in the step's worktree, on Linux x86_64 with shellcheck 0.9.0, the version the GitHub runner image ships.

**The four checks pass on the branch:**

```console
$ bash tools/ci/security.sh secrets
INF 120 commits scanned.
INF no leaks found
$ bash tools/ci/security.sh deps
No issues found
$ bash tools/ci/security.sh sast
Ran 79 rules on 41 files: 0 findings.
$ ZIZMOR_OFFLINE=true bash tools/ci/security.sh workflows      # actionlint, then zizmor
No findings to report. Good job! (3 ignored, 24 suppressed)
$ shellcheck tools/ci/security.sh; echo $?
0
```

**Each check catches what it should.** Each finding was planted in scratch only, and nothing was pushed:

| Planted | Command | Result |
|---|---|---|
| a fake `ghp_` token in a detached scratch commit | `SECRETS_LOG_OPTS=<range> security.sh secrets` | exit 1, `RuleID: github-pat`, `leaks found: 1` |
| the same kind of token with `# gitleaks:allow` | `gitleaks dir`, without and with `--ignore-gitleaks-allow` | exit 0, then exit 1 (`leaks found: 1`) |
| `lodash 4.17.15` in a `package-lock.json` | `security.sh deps` | exit 1, 6 vulnerabilities |
| a Flask route that runs `subprocess` with `shell=True` | `security.sh sast` | exit 1 (`subprocess-injection`, `dangerous-subprocess-use`) |
| the same line with `# nosemgrep` | semgrep, without and with `--disable-nosem` | 0 findings (exit 0), then 3 blocking findings (exit 1) |
| a `tools/ci/.semgrepignore` containing `*`, staged | `security.sh sast` | exit 1, "a .semgrepignore outside the repository root hides code from SAST" |
| a workflow with an untrusted `${{ github.event... }}` in `run:`, unpinned actions and no permissions | `security.sh workflows` | exit 1: actionlint `[expression]`; zizmor `template-injection`, `unpinned-uses`, `artipacked`, `excessive-permissions` |

**Before D4,** the existing workflows had 64 zizmor findings (unpinned actions, template injection, persisted credentials, cache poisoning) and 2 actionlint findings (SC2086 in `docs.yml`, SC2034 in `previews.yml`). All are fixed.

**Not run locally:** zizmor's online audits, which need a token, and the Claude review itself, because no Claude secret exists. Both run on the PR.

**Sources.** Each tool's inputs and flags were read from its own docs at the pinned version. The links and read dates are in [§11](../../specs/dev-environment-and-testing.md#11-ci-workflows) and [§12](../../specs/dev-environment-and-testing.md#12-versioning-and-releases).

**Code review** (`review-code`; findings in [`docs/reviews/code/D4.md`](../../reviews/code/D4.md)):

```text
CODE-REVIEW  verdict=approve  blockers=0  majors=0  minors=1  simplify=0
SECURITY-REVIEW  verdict=approve  blockers=0  majors=0  minors=1
SIMPLIFY  changed=0 files  lines=-0/+0  tests=fail (shellcheck passed; `security.sh workflows` was blocked by permissions and did not run)
```

- **Rounds.** There were three review rounds, run independently and in parallel:
    - round 1: code `changes` (1 major), security `changes` (3 majors);
    - round 2: code `approve`, security `changes` (1 major: a nested `.semgrepignore`);
    - round 3: both `approve`. The two final minors were fixed in `21fd4b1`.
- **code-simplifier** changed nothing: every remaining line is a pin, a guard or a control a reviewer asked for. It could not run the workflow linters itself because of its permissions. The worker ran them on the same tree, `21fd4b1`, and they passed.
