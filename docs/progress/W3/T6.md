## How to test

In a cloud session, Playwright 1.63.0 uses the Chromium pre-installed under `/opt/pw-browsers` (`chromium-1243`). Elsewhere, run `npx --no-install playwright install chromium` first.

```bash
cd tests/e2e && npm ci && npx --no-install playwright test
```

Against the Cloudflare docs preview ([§7.1](../../specs/dev-environment-and-testing.md#71-static-previews-on-cloudflare-pages-now)), browser projects only:

```bash
SPECTIO_E2E_BASE_URL=https://spectio.pages.dev/ npx playwright test --project desktop --project phone
```

## Findings and open questions

1. **`tests/` is not scanned by the SAST check** (SEC-T6-05, deferred). With no root `.semgrepignore`, semgrep's built-in ignore list seems to skip `tests/`. The cause is **[to be validated]** ([§11](../../specs/dev-environment-and-testing.md#11-ci-workflows), "Not scanned"). The proposed fix is a root `.semgrepignore`, which is code-owned. It is for the orchestrator to file in the [inbox](../../reviews/inbox.md); it is not filed yet.
2. **`urls.spectio` is a contract that nothing writes yet.** `base-url.ts` reads it, and [§5](../../specs/dev-environment-and-testing.md#5-isolated-parallel-scenarios) names it, but `dev/scenario.py` does not write it, because no scenario runs Spectio. Until then, `SPECTIO_SCENARIO` always fails with "this scenario does not run Spectio yet".
3. **Two downloads in CI that we do not hash.** `actions/setup-node` downloads Node without checking `NODE_SHA256` of `dev/versions.env`. Whether it checks a checksum of its own is **[to be validated]**. `playwright install` downloads Chromium from Playwright's CDN. Both are recorded under "Not pinned" in [§11](../../specs/dev-environment-and-testing.md#11-ci-workflows).
4. **`e2e.yml` is standalone,** outside `ci-ok`, like `scenarios.yml`. A red run does not block a merge.
