## What changed

- **New check** `tools/claude/check_frontmatter.py`, about 100 lines of Python with PyYAML. It fails, naming the file, when an agent (any `.md` under `.claude/agents/`, recursively) or a skill (`.claude/skills/<name>/SKILL.md`) has:
    - no frontmatter on line 1, or frontmatter that is not closed, does not parse or is not a mapping;
    - an agent `name` that is missing, starts with `-`, contains `:`, is over 256 characters or is used twice;
    - a missing `description` (for skills a repository rule, see the spec row);
    - a field Claude Code does not document;
    - also when a skill folder has no `SKILL.md`.
- **Its tests,** `tools/claude/test_check_frontmatter.py`: 18 cases. 16 write a broken fixture to a temporary folder and expect exit 1 with the file named; one valid fixture and the repository's own `.claude` expect exit 0.
- **New workflow** `.github/workflows/claude-config.yml`: on every PR and on pushes to `main` and `autopilot/integration`, it runs the tests, then the check. It has concurrency, a 5-minute timeout, `permissions: {}` with `contents: read` on the job, `actions/checkout` pinned by SHA (v4.4.0) and `persist-credentials: false`.
- **Owning spec:** [`dev-environment-and-testing.md` §11](../../specs/dev-environment-and-testing.md#11-ci-workflows) has a new `claude-config.yml` row and a sentence under **Workflow conventions**. The §8 skills row now names all eight workflow skills.
- **`CLAUDE.md` corrected** where it no longer matched the repository:
    1. the repository also holds `tools/` and `tests/`;
    2. from wave W3 the work includes build steps for the development layer, not only reviews, spikes and planning;
    3. a spike runs on branch `spike/<name>` (`.claude/skills/spike/SKILL.md:12`);
    4. `review-code` runs `security-reviewer` beside `code-reviewer` (`.claude/skills/review-code/SKILL.md:15`), and the agent table says so;
    5. `ux-reviewer` has `Write` and `Edit` and edits a board when asked to fix it (`.claude/agents/ux-reviewer.md`), so it is named as an exception to "read-only";
    6. a new **Skills** section explains why four skills are missing from Claude's own list, and the check is in **Useful commands**.
- **No agent or skill file changed.** All of them load. The vendored superpowers skills are untouched.
- **Sketch:** `tools/diagrams/d1_claude_config.py`, listed in `docs/assets/media.yaml`.

## Why

Prompt: [next-phase.md · D1](../../playbooks/next-phase.md#d1-validate-the-claude-setup). An agent whose frontmatter breaks does not fail loudly. Claude Code skips a nameless agent, and drops every field of a skill whose YAML does not parse. It also ignores an unknown field ([sub-agents](https://code.claude.com/docs/en/sub-agents.md), [skills](https://code.claude.com/docs/en/skills.md), read 2026-10-27). A reviewer could then vanish from a review round and nobody would notice. The CI check makes that failure loud.

The prompt suggested `claude plugin validate`. On the fixtures below it missed a nameless agent and an unknown field, even with `--strict`, so the check is a small script whose rules come from those two docs pages.
