## What changed

- **Cluster profiles,** [dev-environment §4.2](../../specs/dev-environment-and-testing.md#42-kubernetes-with-kind):
    - `dev/k8s/cluster.sh up mini|kueue`, `down mini|kueue`. `k8s-mini` is one kind node; `k8s-kueue` is a control plane and 2 workers, with Kueue `KUEUE_VERSION`. Both get the namespace `spectio-work` with a `ResourceQuota` (`dev/k8s/base.yaml`).
    - Kueue comes from the release's `manifests.yaml`, checked against `KUEUE_MANIFEST_SHA256`. It is set up with two ClusterQueues and two LocalQueues (`dev/k8s/kueue-queues.yaml`), and the script waits until the visibility API answers.
    - The tools come from `dev/bootstrap.sh`, at the pins of `dev/versions.env`.
    - The repository is mounted into every node at its own path, so that task pods can see the pipeline and its work directory under `.scenarios/` (newly gitignored).
- **`dev/versions.env`:** two new pins:
    - `KUEUE_MANIFEST_SHA256`, computed, because no checksum is published;
    - `NF_K8S_25_10_VERSION=1.2.3`.
- **Scenarios,** `tests/k8s/scenarios.sh`. Each scenario fails on an unexpected outcome.
    - `failures`: one OOMKilled pod, a Job and a Pod over their deadline, and a Job whose pod exits 3.
    - `nf25` and `nf26`: the synthetic pipeline with `-profile test,k8s` plus `tests/k8s/kind.config`. Each runs twice under the head's own token: a happy run that must exit 0, and a tool-error run that must exit 1. No API call may be refused (403). Each grant that neither run used is listed as `unused-grants` (`tests/k8s/api_calls.py`).
    - `kueue-wait`: one Workload admitted and two waiting, with their visibility positions.
    - `runner`: the runner's work done with its own token, and three calls outside its Role that must be denied.
- **RBAC,** `tests/k8s/rbac.yaml`: the measured Roles, which differ from §4 (see [below](#differences-with-the-specs)).
- **CI,** `.github/workflows/pipelines-k8s.yml`, two parallel jobs:
    - `mini`: `failures nf25`;

It has `permissions: contents: read`, no secrets, a 30-minute timeout, actions pinned by SHA, and no `${{ }}` in `run:`. Its fixtures go to the artifacts `k8s-fixtures-mini` and `k8s-fixtures-kueue`. ## How to test

On a machine whose Docker runs on cgroup v2 (not a Claude Code cloud session), from the repository root:

```bash
bash dev/bootstrap.sh && bash dev/k8s/cluster.sh up kueue && \
  for s in kueue-wait nf26 runner failures nf25; do bash tests/k8s/scenarios.sh "$s" || break; done
```

Each scenario prints a `RESULT` line and exits 1 on an unexpected outcome. Fixtures land in `.scenarios/k8s/fixtures/`. `bash dev/k8s/cluster.sh down kueue` removes the cluster. In CI, push a change under `tests/k8s/`, or dispatch `pipelines-k8s.yml` once it is on `main`.

## Differences with the specs

These are findings for TRIAGE3. The specs are not edited. Each line says what the runs above measured, against the owning section.

1. **Nextflow 26.10 engine-head Role** ([schedulers §4](../../specs/schedulers-and-monitoring.md#4-kubernetes-in-detail)).
    - **Not sufficient:** it lacks `pods/status: get` (every poll), `pods: delete` (`jobDelete`) and `jobs/status: get` (a Job with no pod yet, as under Kueue). The spec Role makes the run exit 1 in 7 s ([note](../../research/spike-t4-ci-2026-10-28.md#serviceaccounts-4)).
    - **Over-broad:** `watch`, plain `get` and `list` on Jobs, `get` and `watch` on pods, and `pods/log` were never used.
    - **Measured set:** `jobs: create, delete`; `jobs/status: get`; `pods: list, delete`; `pods/status: get`.
2. **Nextflow 25.10 engine-head Role** (§4).
    - **Not sufficient:** it lacks `pods/status: get`.
    - **Never used:** `get`, `list`, `watch` and `pods/log`.
    - **Measured set:** `pods: create, delete`; `pods/status: get`. This closes "25.10 needing `pods: create`", which §4 marks **[to be validated on k8s-mini]**.
3. **Runner Role** (§4). "What the runner watches" lists Workload objects, but the Role does not grant them: `workloads.kueue.x-k8s.io` is refused. Measured with `workloads: get, list, watch` added, plus the optional visibility `localqueues/pendingworkloads: get`.
4. **Nextflow 25.10 needs the k8s plugin named** (§4, and the `k8s` profile of `tests/pipelines/synthetic/nextflow/nextflow.config`). Without it the run stops with "Unknown executor name: k8s". Spectio's generated config, or the profile, must add `-plugins nf-k8s@1.2.3` or a `plugins {}` block.
5. **"Queued" comes from the visibility API, not from Workload conditions** (§4). The visibility API listed a pending Workload whose `QuotaReserved=False` condition came late or never:
    - run 40669626241: `job-fx-kq-3` had only `PodsReady=False/WaitForStart`, at position 1;
    - run 40668895003: the second pending Workload had no `QuotaReserved=False` after 2 minutes.
6. **An OOM kill produces no event.** It shows only in the pod's `state.terminated` (`failures-events.json`). This supports §4's rule that the runner keeps the last terminal state of each pod.
7. **The head can get a 404 on `jobs/status`** when it reads a Job that it is deleting. That is not a permission refusal, so a check must not count it as one.
8. **The `pipelines-k8s.yml` row and "Required checks"** ([dev-environment §11](../../specs/dev-environment-and-testing.md#11-ci-workflows)). The spec has `helm/kind-action`, nf-core/demo, a `helm install` of the chart, and a reusable workflow called by `ci.yml`. The build differs:
    - it uses `dev/bootstrap.sh` with `dev/k8s/cluster.sh`;
    - nf-core/demo stays in `pipelines-real.yml`;
    - there is no chart yet;
    - it is standalone, triggered by a push with a path filter, nightly and manually, so it is outside `ci-ok`.
9. **The `k8s-mini` row** (§4.2) lists SeaweedFS and the Snakemake Kubernetes executor. They are not built: T4's prompt does not ask for them, so the row is ahead of the build.
10. **Spike findings carried over unchanged:**
    - `FailedScheduling: Insufficient cpu` is normal back-pressure on a small cluster;
    - task pods mount the namespace's `default` ServiceAccount token **[to be validated]** for the security review;
    - inbox #51's "cannot download artifacts" does not hold: this step downloaded its fixtures as artifacts.

    Details are in the [note, Findings for TRIAGE](../../research/spike-t4-ci-2026-10-28.md#findings-for-triage-specs-not-edited).
