## What changed

- **Golden fixtures, new:** `tests/pipelines/synthetic/golden/<engine>-<version>/<scenario>.tsv`.
    - Four directories: `nextflow-26.10.4`, `nextflow-25.10.9`, `nextflow-25.04.8` and `snakemake-9.27.1`.
    - 11 files each, one per PR scenario: 44 files, 512 lines.
    - Each file holds the exit code of every run, then the task outcomes with the columns `run, process, status, exit, attempt, tag, count`.
    - The format and the normalisation rules are in the [research note](../../research/spike-t1-fixture-workflows-2026-10-27.md#golden-fixtures). This page does not repeat them.
- **`tests/pipelines/synthetic/run_scenarios.py`:**
    - `--golden record` writes the fixtures from a run; `--golden check` compares a run with them. On a difference, the scenario fails and `golden.actual.tsv` is written next to the run.
    - `--golden check` fails the whole run when the engine version does not read as `X.Y.Z`, when the version has no fixture directory, or when a PR scenario has no fixture. Only nightly scenarios may have none.
    - `--golden` refuses extra executor arguments: fixtures come from the local executor only.
    - `nf_rows()` reads the Nextflow trace after each run (the previous trace is deleted first). `smk_rows()` reads the Snakemake log.
    - The Snakemake align gate now stops with `--until qc_report align_done`, not `--until align_done` (finding 1 below).
- **`tests/pipelines/synthetic/test_golden.py`, new:** 8 unit tests. They cover the normaliser on sample trace and log text, the target filter, the whole-token sample match (`S1` does not match `S10`), the version and missing-directory errors, and one fixture per PR scenario for every engine version.
- **`tests/pipelines/synthetic/nextflow/nextflow.config`:** the `docker` and `k8s` profiles use `python:3.12` pinned by digest, not `python:3.12-slim`, because Nextflow needs `ps` in the container. The `docker` profile mounts the shared `bin/` read-only (finding 3).
- **`tests/pipelines/synthetic/scenarios.yaml`:** `gate_align_then_resume` now expects `multiqc/general_stats.tsv` after the first run. The `tool_error_then_fixed_resume` title says that Snakemake retries the tool error.
- **`tests/pipelines/synthetic/snakemake/workflow/Snakefile`:** its header names the new align gate targets.
- **`.github/workflows/pipelines-synthetic.yml`** ([spec §11](../../specs/dev-environment-and-testing.md#11-ci-workflows)):

    - the scenario step runs with `--golden check`;

## How to test it

The step test, from the repository root:

```bash
python3 -m unittest tests/pipelines/synthetic/test_golden.py && \
  python3 tests/pipelines/synthetic/run_scenarios.py --engine snakemake --workdir /tmp/t1 --golden check
```

For a Nextflow version, add `--engine nextflow --nextflow <binary>`, for example `--nextflow nextflow-25.10.9`. The engines come from `dev/bootstrap.sh` at the pins of `dev/versions.env`. To see a check fail, change one count in a fixture (for example `ALIGN` 24 → 23 in `golden/<engine>-<version>/happy.tsv`): the scenario fails and `golden.actual.tsv` shows the real outcome.

## Findings and open questions

**Findings.** Four, with their causes and sources, are in the [note, Findings and fixes](../../research/spike-t1-fixture-workflows-2026-10-27.md#findings-and-fixes):

1. The Snakemake align gate skipped the qc stage, because `--until` runs only the target's own dependencies. Fixed in the harness. The generation rule belongs to [checking-scenarios §12.3](../../specs/checking-scenarios.md#123-stage-boundaries), which needs a change: [inbox #48](../../reviews/inbox.md#48-gate-targets-must-include-every-earlier-stages-last-targets-until-runs-only-the-targets-own-dependencies). Nothing is assumed; §12.3 is unchanged until `/apply-findings`.
2. Snakemake `--retries` restarts every failed job, a tool error included; Nextflow's `errorStrategy` here retries only 137, 140, 143 and `Integer.MAX_VALUE`. Spec §10.1 is corrected.
3. The `docker` profile could not run any task (`ps` missing in `-slim`, and a dangling link to `bin/`). Fixed; `oom_real` then gave exit 137 under Docker's memory limit, its first proof.
4. Nextflow 25.04.8 and 25.10.9 report no exit code on a time limit; only 26.10.4 reports 143. Spec §10.1 now gives the code per version.

**For Thomas:**

1. **The rnaseq and sarek gate check moves to the nightly corpus** ([inbox #47](../../reviews/inbox.md#47-assumed-the-rnaseq-and-sarek-gate-stop-and-resume-check-moves-to-the-nightly-corpus)) *(assumed — pending Thomas)*. T1 did not run it. Docker works in the session; the blocker is cost: on CI, rnaseq used about 23 GB of disk and 18 to 23 min per full run, against 26 GB free in the session. Proposed: a per-entry `gate` key in `run_corpus.py`, used by the nightly rnaseq and sarek entries. CH-016 stays open until its first nightly run.
2. **Gate targets on Snakemake** ([inbox #48](../../reviews/inbox.md#48-gate-targets-must-include-every-earlier-stages-last-targets-until-runs-only-the-targets-own-dependencies)). Recommended: a gate after stage N passes `--until` with the last targets of every stage up to N.
3. **Inbox #32, resume.** The observations above fit option B, a child run per resume: Spectio records the Nextflow run name and session ID, and on Snakemake the parent link and the shared directory. The decision stays with Thomas ([inbox #32](../../reviews/inbox.md#32-relaunch-at-a-failed-gate-resume-after-a-failure-and-the-001-gate-verbs)).
