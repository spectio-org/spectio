## What changed

This is the **minimal version** of D6. It does three of the prompt's items. The rest is listed under [Deferred](#deferred-to-a-follow-up-step).

- **`tools/docs/check.py`:** the `build` check now checks the built site for the output of `hooks/progress.py`, in a new function `check_progress_hook()`:
    - it fails when any built HTML page still holds a `spectio:progress-strip` or `spectio:progress-table` placeholder comment;
    - it fails when a page whose source carries a placeholder was not built, or has no rendered strip (`class="sp-waves"`) or table (a `Kind` column header);
    - the pages with placeholders are found from the sources, not listed by hand: today `index.md` and `roadmap/index.md` (strip) and `progress/index.md` (table).
- **`tools/docs/test_check.py`, new:** 7 unit tests, written before the code they test. Six cover the check, on a temporary docs folder and site. The seventh covers the escaping of `%`, CR and LF in the `::error` annotations, which `fail()` now does, so a multi-line message stays one annotation.
- **`.github/workflows/docs.yml`:** the `docs-gate` job runs the unit tests before the docs gate.
- **`mkdocs.yml`:** `exclude_docs: fonts/*.ttf`, so a local Virgil font is never copied into the site.
- **`docs/fonts/OFL.txt`, new:** the copyright line of `excalidraw/virgil`'s `LICENSE.md` and the SIL Open Font License 1.1 text. The font itself is still not committed ([inbox #1](../../reviews/inbox.md#1-virgil-font-licence-blocks-publishing-the-hand-drawn-figures-font)).
- **`tools/diagrams/FONT-LICENSE.md`:** rewritten with the dated sources. The licence is **not confirmed**, because the sources conflict:
    - the repository's `LICENSE.md` declares OFL-1.1, by Ellinor Rapp;
    - the repository's own `Virgil.woff2` names another foundry, says "All rights reserved" and "Freeware for personal use";
    - the depictio copy used locally so far is a third build (`Virgil GS`, Jason Smith, 2002, "All rights reserved"). It must not be committed.
- **`tools/diagrams/README.md`:** the font line points to the unconfirmed status.
- **Figure, new:** `tools/diagrams/d6_progress_hook_check.py` and its four outputs, listed in `docs/assets/media.yaml`.
- **Spec:** [`documentation-system.md`](../../specs/documentation-system.md):
    - [§3.3](../../specs/documentation-system.md#33-the-docs-gate-run-by-autopilot-after-every-step-and-by-ci-on-every-pr) item 1 names the new hook-output check and says where to write a full placeholder;
    - [§1](../../specs/documentation-system.md#1-site-structure): the size of `docs/assets` is now about 11 MB, not 3.3 MB.

The `docs-gate` job already ran the full `check.py`, so the new check runs there on every PR with no other workflow change. The `pr-body` job and the freshness check of the figure SVGs were already in place.

## Why

Prompt: [next-phase.md · D6](../../playbooks/next-phase.md#d6-docs-pipeline-in-ci). Thomas asked for a minimal D6 for this tick. Two reasons for these three items:

- the repository is now public, so the font licence matters;
- a broken `hooks/progress.py` would leave the landing page and the Progress tab without their status, and `mkdocs build --strict` would not notice: an HTML comment is valid output.

No decision-log entry: the step decided no behaviour.

## How to test it

The step test, from the repository root:

```bash
python3 -m unittest tools/docs/test_check.py && python3 tools/docs/check.py --only build
```

To see the check fail on the real site, disable the hook in `mkdocs.yml` (comment out `- hooks/progress.py`) and run `python3 tools/docs/check.py --only build`. Restore the file afterwards.
