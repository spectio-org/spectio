# F6 · Telemetry, install tracking and external analytics

!!! success "Done 2026-10-26 · spec v0.1"

## What changed

- **New spec:** [telemetry and analytics](../../specs/telemetry-and-analytics.md), covering three systems with separate names:
  - anonymous install telemetry, opt-in with a prompt;
  - local activity analytics;
  - a `spectio.analytics` plugin kind for the instance owner's tracker: GA4, Umami, Plausible, Matomo, PostHog.
- The [plugin kinds table](../../specs/architecture-plugins-and-packaging.md#2-plugin-kinds) gained the `spectio.analytics` row.

## Why

Thomas asked for telemetry, install tracking, and a way to plug in external analytics.

## Evidence

- **Source:** an audit of depictio at `0d1aa0a` and the tools' own docs ([research note](../../research/budget-and-telemetry-2026-10-26.md), part B).
- **What upstream statistics cannot do:** GHCR exposes no pull counts through its API, and PyPI counts downloads, not installations.

## Figures and media

None.

## Findings and open questions

- **Default for install telemetry.** The design is opt-in, which keeps the earlier "off by default" decision; depictio is opt-out. The question is in the inbox.
- **Possible depictio bug.** The GA4 loader sets `send_page_view: true` while its comment says page views are left to the app.
