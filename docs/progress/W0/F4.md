# F4 · Authentication and access, with depictio parity

!!! success "Done 2026-10-26 · commit b2687d8 · spec v0.1"

## What changed

- **New spec:** [authentication and access](../../specs/authentication-and-access.md). It covers:
  - instance modes (`single`, `local`, `public`, `demo`);
  - sign-in methods: password, magic links in three forms (sign-in, hand-over, scoped share link), OIDC with PKCE, SAML, depictio trust, CLI device code;
  - sessions and tokens;
  - pipeline provisioning through a scoped service account;
  - a test matrix with Keycloak and Mailpit.
- [API and data model §6](../../specs/api-and-data-model.md) now points to it for sign-in.

## Why

Thomas asked for every auth type he built in depictio, magic links and provisioning included. The share link also gives PR previews and demos access without accounts.

Decision: [decision log, 2026-10-26, auth parity](../../decisions/log.md#2026-10-26-real-pipelines-versioning-staging-access-and-auth-parity).

## Evidence

- **Source:** a code audit of depictio v1.19.2 with file:line references ([research note](../../research/depictio-auth-2026-10-26.md)).
- **Weak points in depictio, fixed in the design:**
  - tickets stored in clear (read in the code);
  - no refresh-token reuse detection (an open TODO in the code);
  - redemption by read-then-save, which is not atomic: *inferred* from reading the code, not reproduced;
  - a shared provisioning key that could provision an admin: *inferred* from reading the code, not reproduced.
