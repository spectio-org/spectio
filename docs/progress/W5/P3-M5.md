### Task 24 · Laptop access: the SSH config entry and `spectio open`

Branch `autopilot/P3-t24`, base `884e5bb`, code head `09eb64e`; 3 commits, 5 files, +817 −0 (`cli/open.py` 195 lines, `open_remote.py` 128, `cli/main.py` +19, the fake `ssh` 81, `tests/test_open.py` 394). Short per-task section ([documentation-system §3.5](../../specs/documentation-system.md#35-docs-per-batch-of-p3-tasks-thomas-2026-11-04)); the figure and the full Evidence are in the batch docs PR. The behaviour is owned by [dev-env §15.3](../../specs/dev-environment-and-testing.md#153-001-on-a-cluster-architecture-and-safety-without-accounts) (Access, req. 8).

- **`spectio open <host>`** (`spectio/cli/open.py`, `cli/main.py`): on the laptop it runs the remote `spectio --help` and reads `~/.spectio/server.json` over `ssh <host>`. With a state file it reaches that node (`--node` overrides it); without one it runs `spectio init` (only if `~/.spectio` is missing) and `spectio serve --detach` on `--node`, the `node` of `clusters.toml`, or `<host>`. It then opens the tunnel on a free local port, gets a ticket from `spectio login --print-link --json`, builds the link itself and opens the browser. Ctrl-C closes the tunnel. Flags: `--node`, `--remote-cmd`, `--local-port`, `--no-browser`. Exit codes: 0, 2 (remote `spectio` missing: the install line is printed, nothing is installed), 3.
- **The `ssh` side** (`spectio/open_remote.py`): every value from the cluster is checked (node, port, PID, ticket); `--` comes before each destination; the tunnel uses `-N -o ExitOnForwardFailure=yes -L 127.0.0.1:<local>:127.0.0.1:<port>` and no host-key option; a remote script is quoted once for `"$SHELL" -lc`, and the arguments of each call with `shlex.join`.
- **`clusters.toml`** (`~/.config/spectio/clusters.toml`): one table per `<host>` with `node` and `remote_cmd` only; the file gets the checks of `spectio.toml`.
- **Review fixes:**
    - round 1: `remote_cmd` runs as one unit, `{ ...; }`, so `module load spectio && spectio` no longer escapes the `~/.spectio` guard of the first start and re-runs `spectio init` (CR-P3T24-01 (r1), blocker);
    - rounds 1 and 2: the error after a failed login names a stale `server.json`, only for a file read by the first call, on the node it names, when ssh itself did not fail (CR-P3T24-02 (r1), CR-P3T24-03 (r2)).
- **Tests:** `tests/test_open.py`, 39 cases, with `tests/fakebin/ssh`, a fake that records its arguments and runs the remote command in a fake shared home. Each of the three fixes was checked test-first by `doc-writer` ([review record](../../reviews/code/P3-t24.md)).
