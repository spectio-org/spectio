It then opens the tunnel on a free local port, gets a ticket from `spectio login --print-link --json`, builds the link itself and opens the browser. Ctrl-C closes the tunnel. Flags: `--node`, `--remote-cmd`, `--local-port`, `--no-browser`. Exit codes: 0, 2 (remote `spectio` missing: the install line is printed, nothing is installed), 3.

- **`clusters.toml`** (`~/.config/spectio/clusters.toml`): one table per `<host>` with `node` and `remote_cmd` only; the file gets the checks of `spectio.toml`.
- **Review fixes:**

### FU-P3-72 · `spectio serve` on a Unix socket

Branch `autopilot/P3-fu72`, base `7886354`. Short per-task section ([documentation-system §3.5](../../specs/documentation-system.md#35-docs-per-batch-of-p3-tasks-thomas-2026-11-04)); the figure and the full Evidence come with the batch. The decision is Thomas's, 2026-11-08, under [inbox #109](../../reviews/inbox.md#109-assumed-writes-need-origin-and-json-as-built-p3-task-16), after the [login-node audit](../../research/2026-11-08-embl-login-node-audit.md#11-recommendation-for-inbox-109-rule-5); the rules are in [dev-env §15.3](../../specs/dev-environment-and-testing.md#153-001-on-a-cluster-architecture-and-safety-without-accounts) req. 1, note 2026-11-08.

- **Which transport** (`spectio_server.serve.started`): on a SLURM environment, or in local mode on a machine `shared_host()` calls shared, `spectio serve` listens on `spectio.sock` in its database directory, never on a TCP port, and mounts the API and the screens there. Local mode on a machine only the user uses keeps `127.0.0.1:<port>`. On TCP, `create_app` still scans the host and never mounts the API on a SLURM environment or a shared host (`on_socket=False`).
- **Refusals, exit 2:** a database directory that is not `0700` and the user's (`checked_db_dir`, as before: nothing is changed); a socket path over 107 bytes, which names the limit and asks for a shorter `--db-dir`; a file at the path that is not a socket; a socket a server answers on. A socket nothing answers on, left by a dead server, is removed and bound again. The socket is `0600` and removed at a clean stop.
- **server.json** records `socket` beside `port`; `port` is the laptop's end of the tunnel, and names the link and the session cookie (`spectio_session_<port>`), since the browser's `Host` is `127.0.0.1:<port>` through the tunnel.
- **The start text** gives `ssh -N -L 127.0.0.1:<port>:<socket> <user>@<node>`, then the link.
- **`spectio login --print-link`** and **`serve --detach`** read the socket from server.json, accept it only as `spectio.sock` in that file's database directory and as a socket of the user, and ask the link over it (`http.client`, never a proxy). **`spectio open`** checks the socket (no `:`, no space, at most 107 bytes) and forwards `-L 127.0.0.1:<local>:<socket>`.
- **Tests:** `tests/security/test_unix_socket.py`, 17 cases, with a real uvicorn on a socket in a temporary directory: the API, the session, the Host allow-list (a loopback name on any port, as a tunnel's local port can differ from the server's: `auth/host.py`) and the event stream over the socket; a refused `0755` directory; a stale, a live and a non-socket file; a too-long path; local mode on a shared host behind a socket, on a lone one on TCP; TCP never mounting the API on a shared host; the login over the socket. `test_open.py` gains 8 cases (the tunnel to the socket, bad sockets), `test_detach.py` two (the tunnel text, a restart after a dead server). The server tests now run as on one person's machine whatever the test host (the `settings` fixture), and the foreground SIGTERM test runs a SLURM environment, so its child is on a socket on any host.
- **Fixed in review:** after an unclean stop (SIGKILL, OOM, a logout that kills the processes) the socket, `server.json` and the key stay behind, and `serve --detach` and `spectio open` waited for a dead server; `new_link` now reads a refused or missing socket as "nothing listens there", as an empty port owner on TCP, and a new server starts (CR-P3FU72-01 r1). A squatted default `/tmp/spectio-<uid>` is refused behind the socket instead of replaced by a `mkdtemp` directory, because the tunnel names that path (SEC-P3FU72-01 r1; dev-env §15.3, Where data lives, note 2026-11-08). The guide says what the refusals print.
- **Not done here, FU-P3-75:** `tests/slurm/e2e.sh` and `tests/slurm/e2e_client.py` still talk to a TCP port (PR #164 owns them and adapts them afterwards); `tests/local/e2e.sh` and `tests/e2e/serve-local.sh` too, so on a host that looks shared, such as this cloud session with its native Slurm, they now find no listener instead of an API that answers 404; `spectio doctor` does not check the socket path's length; how `/tmp` is cleaned on the EMBL nodes, which could remove a long-lived socket file, is **[to be validated]**. Open from the review, all minor: `spectio init` still calls `default_db_dir()` without `fixed`, so on SLURM with a squatted default it makes and prints a `mkdtemp` store that `serve` then refuses (CR-P3FU72-04 r2); `start_text` can still print a TCP tunnel line when `server.json` cannot be read a second time or predates the upgrade (CR-P3FU72-03 r1, SEC-P3FU72-04 r2); the bad-socket cases of `test_open.py` all fail the `db_dir` equality first, so neither the `-L` character regex nor the length check of `check_socket` is tested (CR-P3FU72-02 r1); `serve` accepts a socket path that `spectio open` refuses and prints it unquoted in the pasted `ssh` line (SEC-P3FU72-03 r2); `login --print-link` checks the socket file's owner, not the listening uid (`SO_PEERCRED`), and connects by path after closing the directory (SEC-P3FU72-02 r1, r2); the test file has its own `UnixHTTP`, the same as `login._UnixHTTP` (CR-P3FU72-05 r2, second half). The first half, the socket rule written twice in `login._checked` and `open_remote.check_socket`, was closed by the batch `code-simplifier`: it is now `ports.is_server_socket` ([Batch P3-B07](#batch-p3-b07)).

### FU-P3-74 · a warning when the runs directory is nearly full

No new setting.
- **A `runs_disk` line in `spectio doctor`:** `ok` with the free GiB, the percentage and the path measured; `warn` naming the path and the way out (`SPECTIO_RUNS_ROOT`, `runs_root` in `spectio.toml`, `spectio init --runs-root`, at a larger scratch or group file system). Never a `fail`. The check is one token, `runs_disk`, like the others of the `ok|warn|fail <check> <detail>` format.
- **At launch:** `RunnerLoop._launch` logs `runs_disk <detail>` as a warning just before it submits the head, so once per launch (a launch delivered again after it started adopts and does not warn again), and launches anyway.
- **The install guide** ([Installation](../../installation/index.md)) says where the runs directory goes and how to move it.
- **Tests,** with `shutil.disk_usage` monkeypatched, no disk filled: `test_doctor.py` (the thresholds at 89%/11 GiB, 90%, 9 GiB free and the audit's own `df` numbers, 97%; the nearest existing parent of a missing runs root; an unmeasurable one; the doctor line `ok` and `warn`); `test_local_launcher.py` (a launch on a 97% disk logs the warning once, a redelivery adds none, the launch starts).
- **Open:** the 10 GiB floor is a guess at one run's work directory, **[to be validated]** on real runs; the check does not see quotas (an NFS or Lustre quota can refuse writes on a file system with room).
- **Fixed in review:** a runs root that does not exist yet, under a directory the user cannot search, made `spectio doctor` die with a traceback, because `Path.is_dir()` re-raises `EACCES` on Python 3.11 to 3.13; the search for the nearest parent now sits in the same `try` as `disk_usage`, so the line is a `warn` (SEC-P3FU74-01, `7c338a02`; `test_runs_disk_unsearchable_parent`).
