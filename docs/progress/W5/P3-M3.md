## Why

Prompt: [next-phase.md · P3](../../playbooks/next-phase.md#p3-execution). Step: `P3` in `docs/playbooks/pipeline.yaml` (wave W5, `kind: build`). [P2 §3](../../plans/P2-execution.md#3-m3-served-safely) starts Task 11 after Tasks 3, 8, 9 and 10. In the order of [inbox #80](../../reviews/inbox.md#80-assumed-a-visible-slice-earlier-in-the-p1-order) (a), assumed, it runs before Task 10, for a visible local slice sooner.

- **One process for everything.** The UI, the API, the runner and SQLite run in one `spectio serve` per user ([architecture §7.1](../../specs/architecture-plugins-and-packaging.md#71-processes-and-roles)). Task 11 builds that process and its start, so the runner loop of Task 9 runs for the first time from a command.
- **The port is the only door.** On a shared login node every Unix user can reach a loopback port. 0.0.1 binds `127.0.0.1` only (req. 1). The real guards come next: the session (Task 12) and the Host allow-list (Task 14). Until then the app serves no data (SEC-P3T11-04 (r1), SEC-P3T11-05 (r2)).
- **The database can vanish.** It lives in a node-local temporary directory ([dev-env §15.3](../../specs/dev-environment-and-testing.md#153-001-on-a-cluster-architecture-and-safety-without-accounts), Where data lives), so a purge or a start on another node loses it. The run directories are the source of truth, and the boot rebuilds the index from them. The run directories sit on a shared disk, so each one is read as untrusted input (req. 10).
- **One server per user and node, found from any node.** `serve.lock` stops a second server on the same node. `server.json` in the shared home tells another node, and later `spectio open`, where the server runs (P1 Assumption 9).
