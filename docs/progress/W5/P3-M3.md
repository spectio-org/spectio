### Task 12 · Token link, secrets and sessions

Branch `autopilot/P3-t12`, base `8ca8304`, head `439c2b7`; 2 commits, 24 files, +1044 −94 (+1023 −94 in `packages/`). Short per-task section ([documentation-system §3.5](../../specs/documentation-system.md#35-docs-per-batch-of-p3-tasks-thomas-2026-11-04)); the figure and the full Evidence are in [batch P3-B01](#tasks-12-to-16-batch-p3-b01). The sign-in is owned by [dev-env §15.3](../../specs/dev-environment-and-testing.md#153-001-on-a-cluster-architecture-and-safety-without-accounts) ("Access", req. 2, 8 and 9) and the routes by [api §5](../../specs/api-and-data-model.md#5-endpoint-catalogue-api-v1) (note of 2026-11-06).

- **Three secrets** (`auth/secrets.py`, 95 lines), each 32 bytes from `secrets` and compared in constant time:
    - the server key, a new one at each start in `<db dir>/server.key` (0600); only `POST /api/v1/auth/links` accepts it, and it never opens a session;
    - the link ticket, single use, valid 15 minutes, kept as a SHA-256 digest;
    - the session secret, in memory only (a restart ends every session), kept as a digest too.
- **Routes** (`auth/routes.py`, `auth/static/link.html`, `link.js`): the bootstrap page `GET /auth/link` reads the ticket from the URL fragment, drops it with `history.replaceState`, posts `POST /api/v1/auth/magic-links:exchange` and opens `/`. A used or expired link shows "This link was already used or has expired. Run `spectio login --print-link` on the cluster for a new one."
- **Middleware** (`auth/middleware.py`): `401 unauthenticated` with no data on every other route, `/api/v1` or not. Four routes are exempt (P1 Assumption 8). They answer `Cache-Control: no-store`, `Referrer-Policy: no-referrer` and `Content-Security-Policy: default-src 'self'`.
- **The start:** `spectio serve` writes the key, mints a first link and prints it in the start text, with "Spectio never asks you to paste a link." (req. 14) and `spectio login --print-link` for another.
- **`spectio login --print-link [--json]`** (`cli/login.py`, 120 lines): reads `server.json`, checks the node (req. 8's pattern), the port and the database directory, and on another node prints the `ssh` command and sends nothing. On this node it sends the key only if **every** listener on the recorded port is the caller's uid (req. 9), to `127.0.0.1` with the loopback `Origin` and never through a proxy. `--json` prints `spectio-ticket-v1 {"ticket": "<43 chars>"}`.
- **The listener check changed after review** (`ports.py`, `439c2b7`): `port_owner` returned the first `LISTEN` row at any local address, so the user's own socket on `127.0.0.2:P` could hide another uid's on `127.0.0.1:P`. `port_owners(port)` now returns every listening uid, and login refuses unless the set is exactly the caller's. `serve` keeps `port_owner` for its message (SEC-P3T12-03 (r2)).
- **Tests:** `tests/security/test_req2_secrets.py` (14 tests, the ten of the plan and four more), `packages/spectio/tests/test_ports.py` (1). The existing API and serve tests now sign in (`authed_client`, the `session` cookie). The OpenAPI snapshot adds `/api/v1/auth/links` and `/api/v1/auth/magic-links:exchange`.
- **Spec and inbox:** the api §5 note above; [inbox #105](../../reviews/inbox.md#105-assumed-the-token-link-as-built-p3-task-12), assumed, rules 1 to 7. No section number changed; nothing is blocked.

- **One process for everything.** The UI, the API, the runner and SQLite run in one `spectio serve` per user ([architecture §7.1](../../specs/architecture-plugins-and-packaging.md#71-processes-and-roles)). - **The port is the only door.** On a shared login node every Unix user can reach a loopback port. 0.0.1 binds `127.0.0.1` only (req. 1). The real guards come next: the session (Task 12) and the Host allow-list (Task 14). Until then the app serves no data (SEC-P3T11-04 (r1), SEC-P3T11-05 (r2)).

The run directories are the source of truth, and the boot rebuilds the index from them. The run directories sit on a shared disk, so each one is read as untrusted input (req. 10).
- **One server per user and node, found from any node.** `serve.lock` stops a second server on the same node. `server.json` in the shared home tells another node, and later `spectio open`, where the server runs (P1 Assumption 9).
- **Docs travel with the batch.** Tasks 12 to 16 form one batch, so the figure, the cast and the full Evidence come once, with the batch PR ([autopilot §11](../../playbooks/autopilot.md#11-batches-of-p3-tasks-thomas-2026-11-04)).
