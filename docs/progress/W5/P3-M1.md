**Open points from the worker:**

1. **9 spool fixtures, not 15.** P1 Task 1's test comment says "all 15 fixtures". The 6 Tower-protocol captures of spike T2 are HTTP requests to a Tower endpoint (`POST /trace/create` and the like), not spool events, so they are not converted. `test_one_spool_file_per_bridge_capture` pins one spool file per bridge capture. A note for P1 in the next apply pass.
2. **`snakemake.error` keeps `msg`, with the quoted command hidden.** It is not dropped, because the run's failure message comes from it ([§14.1](../../specs/api-and-data-model.md#141-driven-runs-001)). If the pattern does not match a quote it finds, only the first line is kept (fail closed). Whether other quoting forms leak a command is **[to be validated]** (SEC-P3T1-08, Task 5).
3. **`seq` is per (run, launch, producer).** A bridge's counter starts again in each launch's head process. So [api §8.2](../../specs/api-and-data-model.md#82-ordering-cursors-and-clocks) and [architecture §13.1](../../specs/architecture-plugins-and-packaging.md#131-event-path-spool-first-forwarded-by-the-runner) changed from "per producer and run", with dated notes. The projector (Task 4) compares `source_seq` only within one triple.
