### Task 34 · Server: process and rule states, outputs, SLURM request and efficiency

Branch `autopilot/P3-t34`, base `65d59f6`, one commit. Snakemake and Nextflow are handled alike (Thomas, 2026-11-07): the request and the CPU and memory efficiency per job and per rule or process, with a test of each for both engines. The fields are owned by [api §5](../../specs/api-and-data-model.md#5-endpoint-catalogue-api-v1), the tables by api §7, the formulas by [schedulers §3.6](../../specs/schedulers-and-monitoring.md#36-efficiency-per-job-and-per-process-or-rule), the `sacct` call by [dev-env §15.3 req. 15](../../specs/dev-environment-and-testing.md#153-001-on-a-cluster-architecture-and-safety-without-accounts); each has an as-built note of 2026-11-07.

- **`sacct`** (`spectio/runner/sacct.py`): 16 fields; `TotalCPU` summed over the step rows; `ReqMem` per CPU or per node made whole; partition, account, QOS and `AllocTRES` charset-checked.
- **Migration `0010`** (`0009` was taken by Task 25): `attempts.outputs`, `attempts.slurm`, `run_processes.is_checkpoint`, `runs.engine_settings`, table `run_output_events`.
- **Projectors:** Snakemake `job_info` stores its outputs (in the launch directory, or `<TBD>`), its request (`job_info.resources`) and `custom_options`, and marks a checkpoint; `temp_removed` and `protected` are kept once, for a known output only. Nextflow stores its request from the first trace that has one (the submit) and `onFlowCreate`'s `cleanup` and `clusterOptionsSet`. The freeze marks `checkpoint <name>:` rules.
- **Logger plugin:** `job_info.custom_options` says whether `slurm_extra` was set, never its text (inbox #115 rule 2).
- **`efficiency.py`** (new): the engine's and `sacct`'s ratios, the per-job state, the aggregate. `failure.task_resources` queues every ended job with a job ID on a SLURM run, for both engines.
- **Read API:** task items gain `slurm` and `efficiency`; processes gain `status`, `is_checkpoint`, `lower_bound`, `efficiency`; the run summary gains `tasks.lower_bound`, `open_checkpoints`, `dag_updates`; the run detail gains `engine_settings`; job files gain `outputs`. OpenAPI snapshot regenerated; `web/src/api.ts` gains the types, optional until Task 35.
- **Differences from the plan:** [inbox #116](../../reviews/inbox.md#116-assumed-process-states-outputs-slurm-request-and-efficiency-as-built-p3-task-34), assumed.
