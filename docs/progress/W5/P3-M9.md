- **A resized job reads `available`.** Its older RESIZING records are left out. The final record is the row, with CPU and memory None, since the steps under the RESIZING record are not summed. Two final records in one directory still give no row.
- **Steps join the job line just before them**, with the same base ID, and nothing else.
- **Each call has its own 16-character delimiter** and `TZ=UTC`; a line that does not split into the 17 fields is dropped. `WorkDir` comes before `Submit`, not last (SEC-P3FU53-02): a line separator inside a WorkDir leaves two pieces and neither has 17 fields, so no truncated WorkDir binds a job and nothing is forged. Only `\n` is tested.
- **The server side.** The expected directories are the job's path and its `realpath`, computed in the file pool when the job is first asked: only for IDs that are SLURM job IDs, one resolve job per run at a time, 100 directories each, every result kept as it is computed (CR-P3FU53-01, SEC-P3FU53-01). A job with no directory is never asked. A run that asks for a job while a call for it is in flight is queued again, with no try counted.
