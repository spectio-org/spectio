## Findings and open questions

**What the spike found:**

1. **No real clusters in cloud sessions.** sind and kind do not run, because the VM boots with a hybrid cgroup v1 layout. cpu, memory and pids stay on v1, which the sandbox itself uses, and a session cannot change that. SLURM and Kubernetes scenarios therefore run in CI and on a developer machine ([note, result](../../research/spike-cloud-env-2026-10-26.md#result)).
2. **Docker must be started in every session.** It is installed but not running, and a running process is not kept in the environment snapshot. The note proposes a SessionStart hook that starts `dockerd --registry-mirror=https://mirror.gcr.io`.
3. **Docker Hub rate limit.** It answered 429 after about 6 anonymous pulls; the `mirror.gcr.io` mirror fixed it.
4. **GitHub repository scope.** `releases/latest` and the API return 403 for repositories not attached to the session. Downloads from a pinned tag pass. Bootstrap must pin every version ([note, network](../../research/spike-cloud-env-2026-10-26.md#network)).
5. **The mermaid command in `CLAUDE.md` fails as root.** It needs `-p` with a `--no-sandbox` puppeteer config. The rule belongs to [`documentation-system.md`](../../specs/documentation-system.md) (follow-up 7 in the note).
6. **Allowlist and budget.** The note gives a 14-line [Custom allowlist](../../research/spike-cloud-env-2026-10-26.md#recommended-custom-allowlist) and a [setup-script budget](../../research/spike-cloud-env-2026-10-26.md#setup-script-budget): about 60 s measured, at most 150 s as a target.
