## Findings and open questions

**The five findings that matter most** (as ranked in the [review file's summary](../../reviews/R5-security.md#summary)):

1. [SEC-101 · blocker](../../reviews/R5-security.md#sec-101-blocker-a-runners-unix-account-is-not-tied-to-the-principals-who-launch-on-it): a runner's Unix account is not tied to the people who launch on it. On a group environment, any `launcher`, or any editor who adds a `script:` binding, runs code as a colleague's or an admin's cluster account. Related to [R1 SR-014](../../reviews/R1-consistency.md#sr-014-major-which-unix-account-runs-a-launch-on-a-group-owned-environment-is-undefined).
2. [SEC-102 · blocker](../../reviews/R5-security.md#sec-102-blocker-single-mode-trusts-loopback-but-loopback-is-shared-by-every-user-of-a-login-node): `single` mode trusts `127.0.0.1`. On an HPC login node, an MVP target, every other user can drive the owner's runs as the owner, and so can a web page through DNS rebinding. Same core problem as [R1 SR-031](../../reviews/R1-consistency.md#sr-031-major-single-user-mode-trusts-loopback-but-loopback-is-shared-on-a-login-node), rated major there; R5 adds the browser path and rates it a blocker.
3. [SEC-104 · major](../../reviews/R5-security.md#sec-104-major-no-endpoint-action-scope-role-matrix-so-every-endpoint-has-a-principal-and-a-can-cannot-be-checked): there is no endpoint → action → scope → role matrix, so "every endpoint has a principal and a `can()`" cannot be built or tested. IDs in request bodies and plugin routes are the likely gaps.
4. [SEC-113 · major](../../reviews/R5-security.md#sec-113-major-identities-are-linked-by-email-across-idps-and-group-sync-is-not-namespaced-or-kept-away-from-protected-groups): identities are linked by email across IdPs, including depictio, which cannot verify email. Group sync is not namespaced, so an IdP group named `admin` can lead to account takeover or admin rights.
5. [SEC-115 · major](../../reviews/R5-security.md#sec-115-major-a-server-compromise-is-code-execution-on-every-runners-unix-account-runners-hold-no-local-policy): a server compromise means code execution on every runner's Unix account, because runners enforce no local policy. The file proposes a runner-side `runner.toml` that the runner enforces whatever the server says.
