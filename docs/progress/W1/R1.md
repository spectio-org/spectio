## Findings and open questions

**The five findings that matter most** (the review file explains the choice):

1. [SR-001 · blocker](../../reviews/R1-consistency.md#sr-001-blocker-the-engine-server-ingest-contract-is-undefined): no contract for how engines send events to the server. Nothing defines the payload, the run handshake for runs started from a terminal, the ingest credential and scope, or what the plugin does when the server is down. Decision 0001 removed Tower's `/trace/create` with no replacement. Found by 3 of the 4 reviewers.
2. [SR-002 · blocker](../../reviews/R1-consistency.md#sr-002-blocker-runner-server-protocol-no-owner-two-transports-two-credential-lifetimes): the runner ↔ server protocol has no owner. api §5 says WebSocket; architecture §7.6, admin §3.2 and the log say outbound HTTPS pull. There is no command catalogue and no ack or replay rule. The runner credential rotates in one spec and lives until revoked in another. Found by all 4 reviewers.
3. [SR-003 · blocker](../../reviews/R1-consistency.md#sr-003-blocker-check-providers-run-on-the-server-in-three-specs-on-the-runner-in-three-others): check providers run on the server in three specs and on the runner in three others. This decides the runner's dependencies and whether its 80 MB budget holds.
4. [SR-004 · blocker](../../reviews/R1-consistency.md#sr-004-blocker-spectioyml-has-four-shapes-and-no-owner-of-its-schema): `spectio.yml` has four incompatible shapes and no owner. Proposal: a new checking §12 reference backed by a JSON Schema.
5. [SR-007 · major](../../reviews/R1-consistency.md#sr-007-major-phase-labels-do-not-map-to-release-stages-and-the-phase-tables-contradict-each-other): phase labels (MVP, 1b, 1c, 2, 3) do not map to release stages (0.1, alpha, beta, 1.0). "1b" means four different things. Proposal: a new dev-env §15 "what ships in which stage" table. The WES facade's four dates are SR-010.

The fifth blocker, [SR-005](../../reviews/R1-consistency.md#sr-005-blocker-tasks-names-two-different-tables-id-spaces-and-endpoint-families), is two tables both named `tasks`. The fix is a rename.
