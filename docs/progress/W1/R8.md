## Findings and open questions

**The five findings that matter most** (as ranked in the [review file's summary](../../reviews/R8-depictio.md#summary)):

1. [DL-101 · blocker](../../reviews/R8-depictio.md#dl-101-blocker-runner-side-depictio-cli-ingest-needs-two-instance-wide-secrets-that-131-forbids-on-runners): the runner-side `depictio-cli ingest` of api §13.3 needs depictio's instance provisioning key, which can mint 1-year shared tokens for any email, admins included, and depictio's S3 write secret. §13.1 forbids both on runners, and on Compose the S3 endpoint has no host port. Extends [R2 FC-003](../../reviews/R2-open-validations.md#fc-003-major-depictio-cli-ingest-user-needs-depictios-instance-provisioning-key-not-a-short-lived-credential), whose fix removes the key but not the S3 secret.
2. [DL-102 · major](../../reviews/R8-depictio.md#dl-102-major-trusting-depictio-jwts-no-iss-aud-or-email-claims-revocation-lives-only-in-depictios-database-and-there-is-no-browser-hand-over): depictio JWTs carry no `iss`, `aud`, email or `jti`, revocation is a database lookup, and the browser session lives in depictio-origin `localStorage`. v1 trust must go through `GET /auth/me`, and before SSO "one login for both" exists only in the CLI. Extends [R5 SEC-120](../../reviews/R5-security.md#sec-120-major-depictio-jwt-trust-accepts-tokens-spectio-cannot-audience-check-or-revoke-and-maps-depictio-admin-to-spectio-admin).
3. [DL-103 · major](../../reviews/R8-depictio.md#dl-103-major-a-depictio-dashboard-can-be-embedded-only-from-the-same-origin-a-filter-message-protocol-already-exists-in-another-shape): the gate-time Dashboard tab cannot embed depictio from another origin: the frame is refused, or it loads without a session **[to be validated]**. A `depictio-embed` filter and ready message protocol already exists, so request 9 needs rewording.
4. [DL-104 · major](../../reviews/R8-depictio.md#dl-104-major-the-catalogue-as-a-gate-check-source-multiqc-outputs-have-no-columns-and-half-of-the-recipes-cannot-run-standalone): 61 MultiQC-section catalogue outputs have no columns, and 186 of 339 recipe modules use `dc_ref`, which the standalone runner skips with exit 0 and no table. This affects 0.1, whose focus is checks. Related to [R1 SR-023](../../reviews/R1-consistency.md#sr-023-major-gate-checks-depend-on-the-depictio-catalogue-but-01-has-no-depictio).
5. [DL-105 · major](../../reviews/R8-depictio.md#dl-105-major-run_tag-spectio-run-id-cannot-be-set-and-attach-run-does-not-give-one-complete-run-per-spectio-run): `run_tag = Spectio run ID` cannot be set, because a flat run is named after its directory. `--attach-run` recipe collections read only the first run, and `--result-json` returns no run ID. The proposal is to ingest through a `<run-id>` symlink and use one depictio project per Spectio run.
