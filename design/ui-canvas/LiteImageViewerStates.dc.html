During the view: the status line

A problem after the first tile does not replace the viewer: the tiles drawn stay, and the status line above the canvas (role="status") says what stopped.
X · BUDGET REACHED (READS)
Spectio stopped reading tiles: 2,000 reads.
Reload starts a new budget and keeps the plane, the channels and the zoom.
Y · BUDGET REACHED (BYTES)
Spectio stopped reading tiles: 256 MiB read.
The limits are FU-P3-102e's to set from a measured fixture (ui-spec §4.4.1, [to be validated]).
Z · TILE ERRORS
Some tiles could not be read.
Retry asks those tiles again; the budget is not reset.
Data: fixture names shaped on nf-core/mcmicro and IDR; the pictures are the board thumbnails of design/ui-canvas/images (SOURCES.md), as LiteImageViewer. Texts, caps and the link cases from ui-spec §4.4.1 (imaging note of 2026-11-09, States) and dev-environment-and-testing §15.3 req. 19; the data path from api §5.3.1. A state in the viewer's place has the role of the file page's other states (role="note" here, as LiteFilePreviewStates, until FU-P3-98 settles it); it offers Download where the file is one file and Copy path for a folder; 404, 409, 410, 503 and any other follow the file page's mapping. Every button is a native <button> or <a>; Copy path on a folder is named after it. Phone: MLiteImageViewer.
